# Proposal: m6-compare-tab

## Why

Change 5 вехи M5+M6 (§7 плана `docs/plan-m5-m6-policy.md`) — экран вердикта. Сетка
миров `data/worlds/{a-base,b-reactive,c-mlp,d-lstm}.db` сгенерирована, переключатель
миров (`m6-worlds-ui`) позволяет смотреть ветки по одной, но ответа на главный
вопрос вехи — «что дал ML-тариф против A и B на одной неделе» — числом в продукте
нет: сравнивать приходится ручным SQL. Без этого change'а DoD вехи («таблица
4 веток × исходы + кумулятивная выручка; числа сходятся с ручным SQL») не закрыт.

## What Changes

- **REST `GET /api/ml/compare`** — исходы тест-недели (дни
  `ml.train_days + 1 … + ml.test_days`) по каждой ветке реестра миров, read-only к
  БД веток: поездки (completed), невыполненные (unfulfilled), среднее ожидание
  подачи (`pickup_at − created_at` завершённых, мин), выручка
  (Σ (`base_boarding + per_min_rub × path_min[o][d]`) × `price_multiplier`
  завершённых, прецедент §10.15 M2), доля дефицитных зона-бакетов (правило
  контракта); дельты к A в процентах; ряд кумулятивной выручки по часам
  тест-недели на ветку; точность тень-моделей (MAE спроса, F1 дефицита по
  горизонтам 15/30) — **только против факта ветки A**.
- **Вкладка «Сравнение»** — третья вкладка таб-бара: таблица веток × исходов
  (лучшее значение подсвечено, дельта к A под числом), канвас-график расходящихся
  линий кумулятивной выручки, таблица точности против A с явной подписью, почему
  точность внутри C/D не показывается (self-fulfilling prophecy, §11 M3).
  Канвас — по прецеденту `m3-ml-tab`: guard на скрытый канвас + перерисовка на
  показе вкладки; данные загружаются лениво при первом открытии.
- Отсутствующая БД ветки — строка «не сгенерирована» без ошибки; ни одной БД —
  пустое состояние вкладки с подсказкой команды генерации.
- План `§7` упоминает `/api/ml/worlds`: перечень миров уже отдаёт `GET /api/worlds`
  (`m6-worlds-ui`) — дубль не вводится.
- Сверх плана — столбец «доля дефицита»: на реальной сетке невыполненных ≈ 0 во
  всех ветках (город с запасом водителей, дефицит — по правилу соотношения), так
  что без него главный эффект политик в таблице не виден. Исходы плана остаются.

Не входит (§2 плана): пересчёт/регенерация миров, выбор горизонта/недели в UI,
точность внутри B/C/D, статистические тесты значимости, экспорт отчёта.

## Capabilities

### New Capabilities

- `web-compare-tab`: REST сравнения веток (исходы тест-недели, дельты к A,
  кумулятивная выручка, точность против A) и вкладка «Сравнение» с таблицами и
  канвас-графиком.

### Modified Capabilities

- `web-ml-tab`: MODIFIED — требование «Таб-бар „Город / Лаборатория“» расширяется
  третьей вкладкой «Сравнение» с тем же правилом сохранения воспроизведения.

## Impact

- Код: новый `app/compare.py` (чистые функции расчёта исходов по БД ветки),
  `app/server.py` (`/api/ml/compare`, кэш результата по mtime файлов БД),
  `app/static/index.html`/`app.js`/`charts.js`/`style.css` (вкладка, таблицы,
  график).
- Данные: `data/worlds/*.db` — только чтение (`mode=ro`); новых данных нет.
- Тесты: новый `tests/test_web_compare.py` (крошечные tmp-БД веток с ручным
  расчётом, кэш, отсутствующие БД, статика вкладки).
- Зависимости: новых нет. Последний change вехи — дальше отчёт вехи (§9 DoD).
