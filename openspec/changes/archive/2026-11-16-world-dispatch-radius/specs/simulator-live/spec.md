## MODIFIED Requirements

### Requirement: Состав записи минуты MinuteRecord

Запись минуты SHALL быть иммутабельной и содержать поля: `t` — сим-минута записи; `is_rain` — дождь в минуту `t`; `price_mult` — фактический множитель тарифа каждой зоны на минуту `t` кортежем по возрастанию `zone_id` (при заданном `price_fn` — его значение, иначе тариф среды); `free_by_zone` — снапшот числа свободных водителей по зонам на конец минуты кортежем по возрастанию `zone_id`. События минуты SHALL сгруппированы по типу и использовать внутренний id заказа движка (счётчик с 1, порядок создания, тот же порядок, что `trip_id` вставки) как сквозную нить: `spawns` — созданные в минуту заказы (internal_id, origin, dest, множитель заказа); `assignments` — назначения минуты (internal_id, driver_id, `driver_zone` — зона водителя в момент назначения, origin, dest, `pickup_at`, `dropoff_at` — сим-времена, известные в момент назначения); `dropoffs` — высадки минуты (internal_id, driver_id, зона высадки); `expiries` — истечения минуты (internal_id, origin); `cancellations` — отказы пассажиров минуты от долгой подачи (internal_id, origin, `pickup_min` — подача отвергнутого водителя), в порядке обхода очереди диспатча; при выключенных отказах кортеж пуст. Времена событий SHALL быть наивными datetime с секундами 00.

#### Scenario: События минуты согласованы с моментами

- **WHEN** заказ создан в минуту t1, назначен в минуту t2 и довезён до высадки в минуту t3
- **THEN** запись t1 содержит spawn с его internal_id, запись t2 — assignment с тем же internal_id, у которого `pickup_at`/`dropoff_at` — будущие моменты; запись t3 — dropoff с тем же internal_id, и `t3` равна `dropoff_at`, предсказанному в assignment

#### Scenario: Каждой строке trips соответствует цепочка событий

- **WHEN** прогон завершён и его поток событий сверен с таблицей `trips`
- **THEN** каждой строке `completed` соответствует тройка spawn → assignment → dropoff с тем же internal_id, у которой `t` записей равны `created_at`, `assigned_at` и `dropoff_at` строки, а зоны событий равны `origin_zone`/`dest_zone` строки; каждой строке `unfulfilled` — пара spawn → expiry без assignment между ними; каждой строке `cancelled` — пара spawn → cancellation без assignment; заказов в потоке нет других

#### Scenario: Полный охват событий равен итогам прогона

- **WHEN** события суммированы по всем записям прогона
- **THEN** spawns = `trips_total`, assignments = dropoffs = `completed`, expiries = `unfulfilled`, cancellations = `cancelled` из `Summary` прогона

#### Scenario: Свободный парк согласован с активными поездками

- **WHEN** на минуту `t` из потока восстановлено множество активных поездок (назначения без закрывших их высадок)
- **THEN** сумма `free_by_zone` записи равна числу водителей конфигурации минус число активных поездок на конец минуты `t`; отказ пассажира не меняет число свободных водителей
