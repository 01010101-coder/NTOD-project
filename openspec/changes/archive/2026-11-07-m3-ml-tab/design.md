# Design: m3-ml-tab

## Context

Сервер воспроизведения (`app/server.py`, `create_app`) живёт своим миром:
фоновый прогон движка наполняет `ReplayLog`, REST `/api/city` и `/api/metrics`
читают его, WS раздаёт записи. Веха M3 создала параллельный статичный контур:
`data/m3_epoch.db` (37 дней; `forecasts` — 96 480 строк: 4 `model_version` ×
2 горизонта × 12 060; тест-эпоха 2026-12-02 … 2026-12-08) и `artifacts/`
(`summary-2026-11-06.json`, `mlp-v1-2026-11-06/` и `lstm-v1-2026-11-06/` с
`metrics.json` + `loss.json` по эпохам). Вкладка «Лаборатория» — читатель этого
контура; контракт страницы города (`web-city-ui`) менять нельзя.

Форматы данных (закреплены changes `m3-train-cli`/`m3-inference`):
`metrics.json` — `{model_version, arch, window_hours, best_epoch, …}`;
`loss.json` — массив `{epoch, train{…}, val{…}}`;
`summary-<YYYY-MM-DD>.json` — `{date, summaries: [{model_version, regression,
deficit, calibration}]}` по 4 моделям.

## Goals / Non-Goals

**Goals:**

- Четыре read-only REST-эндпойнта `/api/ml/*` поверх БД эпохи и артефактов.
- Вкладка «Лаборатория» со всеми блоками спеки при нулевых изменениях поведения
  города.
- Изолированные тесты на временных фикстурах (маленькая SQLite-эпоха +
  мини-артефакты), без зависимости от 74-МБ БД.

**Non-Goals:**

- Миграция существующего графика города на новый хелпер (риск регресса
  city-canvas без выгоды).
- WS, пуш, live-обновление лаборатории: данные walk-forward статичны.
- Индексы/схема БД: подключение read-only, схема не трогается.
- Seek-связка вкладок, «Сравнение» веток, параметры обучения — вне вехи.

## Decisions

1. **Источник и точка подключения.** БД эпохи — существующий `cfg.ml.db`
   (ключ завёден `m3-dataset`); каталог артефактов — новый необязательный
   параметр `create_app(..., artifacts_dir: Path = Path("artifacts"))`,
   дефолт — cwd-конвенция CLI `python -m ml train` (пишет в `artifacts/` от
   текущего каталога). Альтернатива — ключ `ml.artifacts_dir` в конфиге —
   отвергнута: это не параметр мира, расширять `MlCfg` и канон-тесты ради
   каталога по умолчанию незачем; параметр даёт тестам tmp_path бесплатно.

2. **Чтение SQLite — соединение на запрос, read-only**
   (`sqlite3.connect(f"file:{path}?mode=ro", uri=True)`). Выборка одного
   графика (зона × модель × горизонт) — ≤ 2 010 строк, полный скан 96 тыс.
   строк при отсутствии индексов — миллисекунды; кэш и состояние в `app.state`
   не нужны, а пересоздание данных CLI-ем не требует инвалидации.
   Альтернатива — постоянное соединение в `app.state` — отвергнута: состояние
   без выгоды.

3. **Факт соединяется на сервере.** `/api/ml/forecasts` возвращает каждую
   строку прогноза вместе с фактом бакета `ts + horizon_min` (`actual_requests`,
   `actual_free_drivers`, `actual_deficit`) — график «факт vs прогноз»
   собирается одним запросом. `actual_deficit` считается правилом контракта;
   реализация переиспользуется (единая функция правила, как в агрегаторе
   симулятора и метриках ML), копия правила не плодится. Пропущенный факт-бакет
   даёт `null`-поля (хвост тест-эпохи), клиент такие строки в линиях пропускает.

4. **Сводка — passthrough, не пересчёт.** `/api/ml/summary` отдаёт файл
   `summary-*.json` с максимальной датой в имени (формат имени закреплён
   `m3-inference`), 404 с сообщением при его отсутствии. Пересчёт метрик из
   `forecasts` на лету отвергнут: сводка CLI — канонический источник, второй
   источник правды расползается числами.

5. **Список моделей — слияние двух источников.** Наивы — `SELECT DISTINCT
   model_version` из `forecasts` (артефактов у них нет), сети — каталоги
   `artifacts/*/` с валидным `metrics.json`; кривая loss (`loss.json`) вшита в
   ответ (≤ 100 эпох, копейки). Порядок: наивы, затем сети по имени версии.
   `/api/ml/errors` считает сервер: остаток `pred_requests − actual_requests`
   по `ts`, гистограмма — 20 равных бинов по диапазону остатков, `by_hour` —
   MAE по часу суток `ts`; строки без факта пропускаются.

6. **Переключение вкладок — атрибут на `<body>`, CSS скрывает секции.**
   Таб-бар под шапкой; клик ставит `data-tab="city|lab"`, стили
   `body[data-tab="lab"]` прячут город и показывают лабораторию. Рендеры города
   и WS не трогаем: скрытый канвас продолжает рисоваться — принятая цена
   (мала) за нулевой риск регресса рабочего конвейера. Данные лаборатории
   грузятся лениво при первом открытии вкладки, дальше — по смене селекторов;
   выбор по умолчанию: зона — первая из `/api/city`, модель — последняя сеть,
   горизонт 15, таргет «спрос».

7. **Графики — добавляемый multiline-хелпер в `charts.js`.** Хелпер принимает
   серии `[{name, color, points}]` на оси времени, опциональную полосу-заливку
   интервалов (для `deficit_prob > 0.5`) и живёт рядом с существующим кодом
   графика города, который не мигрирует (Non-Goal). Стиль — текущая тёмная
   палитра и чипы; селекторы — как у графика метрик города.

8. **Тесты** (`tests/test_web_ml_tab.py`): фикстура строит маленькую SQLite-эпоху
   через `storage.schema.init_db` + точечные вставки `zone_metrics_5min` и
   `forecasts` (2 зоны × несколько ts × 2 горизонта × 1–2 модели) и tmp-каталог
   артефактов (`metrics.json`, `loss.json`, `summary-*.json`); приложение —
   `create_app(cfg с tmp-путём, artifacts_dir=tmp, tick_interval=None)` через
   TestClient. Статик-тест проверяет таб-бар и id секций лаборатории;
   существующий страничный тест (`tests/test_web_server.py`) при необходимости
   расширяется, городские сценарии не меняются.

## Risks / Trade-offs

- [Скрытый канвас города рисует вхолостую] → сознательное упрощение; если
  profiling покажет нагрузку — guard видимости в рендере отдельной правкой.
- [Форматы артефактов сменятся в будущем] → чтение терпимо к лишним ключам;
  отсутствие файлов — пустые состояния и 404, не 500 (требование спеки).
- [Read-only БД без индексов под фильтры] → объёмы малы (96 тыс. строк),
  скан — миллисекунды; индексы не создаём (подключение ro).
- [Браузерный кэш статики при ручной приёмке] → перед проверкой грузить
  статику с `cache: 'reload'`; вкладку проверять после завершения fetch, не по
  rAF (подвисание rAF в IAB-панели — известная ловушка smoke-тестов).
- [Наивы без артефактов выглядят «неполными» в панели модели] → по спеке у
  наивов нет loss-графика: панель показывает метки `kind="naive"`.

## Migration Plan

Изменение чисто аддитивное: эндпойнты и вкладка добавляются к работающему
серверу; данных и схем не мигрируем. Откат — удалить вкладку и эндпойнты,
город не затронут.
