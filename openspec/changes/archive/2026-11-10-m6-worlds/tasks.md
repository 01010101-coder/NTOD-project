## 2. Тень-прогнозы обеих моделей

- [x] 2.1 `ShadowForecaster` в `simulator/policy.py` (design решение 3): две сети
  из свежайших каталогов семейств, питание строками закрытых бакетов, батч-прогон
  `predict_windows` на окна всех зон при полном комплекте зон бакета; прогнозы
  только с границы активации (день `ml.train_days + 1`), момент прогноза —
  последний закрытый бакет, строки контракта обоих горизонтов 15/30 с
  `model_version` = семейство; отсутствие каталога семейства — `FileNotFoundError`
  при построении (guard до старта). Verify: тест на мини-артефактах — после
  короткого прогона тень выдала строки обоих семейств с границы активации
  (бакет × зона × 2 горизонта × 2 семейства), до границы ни одной; тест «нет
  артефакта семейства» — исключение до старта
- [x] 2.2 Тень в `generate_branch`: параметр `shadow: bool = True` — наблюдатели
  тени передаются в `run`, строки пишутся в `forecasts` БД ветки буфером с flush
  на бакет (`insert_forecasts`); `shadow=False` — тени нет, артефакты не нужны
  (guard только у контурных веток, как в m6-policy); при `shadow=True` guard
  каталогов обоих семейств у любой ветки реестра до старта (CLI — exit 2).
  Verify: тесты — `a-base` с тенью на мини-артефактах: `forecasts` непуста с
  дня активации, PK принимает все строки; `a-base` c `shadow=True` без
  каталогов → exit 2/исключение, БД без строк; `b-reactive` с `shadow=False` без
  каталогов — генерируется (регресс m6-policy)
- [x] 2.3 Чистота наблюдения и детерминизм тени (спека simulator-policy):
  прогон с тенью и без на одном seed — `trips`/`zone_metrics_5min` побайтово
  равны; повторный прогон с тенью — `forecasts` побайтово равна. Verify: тесты
  на коротком прогоне с мини-артефактами (экспорт таблиц, прецедент
  `epoch_check`); существующие тесты `tests/test_sim_branches.py`,
  `tests/test_sim_policy.py` зелёные

- [x] 4.2 Честность вмешательств (DoD §9): доли срабатываний c-mlp и d-lstm из

  генерации зафиксированы в отчёте задачи; расхождение > 1 п.п. — стоп и
  разбор (не тишина, §8.4)
  - Отчёт: повторная генерация d-lstm — побайтово та же БД (md5 trips/metrics/
    forecasts `7ccf7d…`/`7cca9a…`/`548c51…` совпадают, fire_rate 0.135 идентичен)
    — детерминизм PASS. Замкнутый контур дней 31–37: c-mlp 7.3 % (891/12126),
    d-lstm 13.5 % (1642/12126) — разрыв 6.2 п.п. > 1 п.п., стоп и разбор:
    офлайн-калибровка цель выполнила точно (val-дни 29–30 эпохи: 10.0 % и
    10.2 %, разрыв 0.2 п.п., `policy-calibration.json`), расхождение рождает
    сам замкнутый контур — тариф модели меняет спрос и её же распределение
    прогнозов (MLP само-демпфируется вниз, LSTM дрейфует вверх), и офлайн-δ
    этот разрыв не сжимает без подстройки по замкнутому прогону, которая
    нарушает «правила до эксперимента» (§4 плана). Зафиксировано честно по
    §8.4: база честности сравнения C/D — равные калиброванные δ + измеренный
    контурный разрыв, отражается в отчёте вехи.
