# Proposal: m6-worlds

## Why

Change 3 вехи M5+M6 (§7 плана `docs/plan-m5-m6-policy.md`): вердикт «ML-тариф против
A и B» имеет смысл только при честном сравнении — равной частоте вмешательств у веток
C и D (δ-калибровка, §4) и равной информационной базе во всех мирах (тень-прогнозы
обеих моделей в каждой ветке, решение 7). Сейчас `policy.shift = {mlp: 0.0,
lstm: 0.0}` — стартовые значения, а в `data/worlds/` есть только `a-base.db`
(change `m6-rng-branches`): сетки миров, на которой строятся UI (change 4) и вкладка
«Сравнение» (change 5), не существует.

## What Changes

- **δ-калибровка честности**: офлайн-процедура и CLI — на валид-днях 29–30
  `data/m3_epoch.db` walk-forward-инференсом M3 (без ретрейна) подобрать
  `shift.mlp`/`shift.lstm` так, чтобы частота срабатывания ступеней каждой модели
  ≈ `policy.target_fire_rate` (допуск ±1 п.п.); результат —
  `artifacts/policy-calibration.json` (δ, частоты до/после, факт достижения цели)
  и обновление `policy.shift` в `config.yaml`.
- **Тень-прогнозы**: в каждой ветке обе модели (mlp/lstm) инференсатся независимо
  от политики и пишут строки контракта `forecasts` в БД своей ветки (`model_version`
  = семейство) — тумблер «прогноз» и «факт vs прогноз» работают во всех мирах
  (решение 7 плана); наблюдение тени не меняет мир (rng не тратится).
- **Генерация сетки миров**: одна операция (функция + `--all` CLI) генерирует все
  ветки реестра — `a-base` / `b-reactive` / `c-mlp` / `d-lstm` (политика активна
  дни 31–37), с тень-прогнозами и диагностикой срабатываний контурных веток;
  guard всех целевых БД до старта.
- **Реестр миров**: программный перечень миров поверх `policy.worlds_dir` (имя,
  файл БД, метка политики, наличие файла) — производная реестра веток, список, а
  не скан каталога (§2.7 плана); потребитель — change `m6-worlds-ui`.
- **Автотесты честности сетки**: побитовое совпадение дней 1–30 (до границы
  активации) между всеми парами веток; повторная генерация ветки побайтово
  совпадает, включая `forecasts`; guard-семантика расширена — тень требует каталоги
  артефактов обоих семейств у любой ветки реестра.

Не входит (§2 плана): ретрейн/Platt-калибровка сетей, регенерация `m3_epoch.db`,
гистерезис ступеней, новые зависимости.

## Capabilities

### New Capabilities

_(нет — все требования ложатся в существующие capability контура и веток)_

### Modified Capabilities

- `simulator-policy`: ADDED — δ-калибровка честности (офлайн-подбор сдвигов по
  валид-дням эпохи M3, артефакт `policy-calibration.json`, обновление конфига);
  ADDED — тень-прогнозы обеих моделей (наблюдатель контура, независимый от
  политики, чистое чтение, детерминизм).
- `simulator-branches`: ADDED — генерация сетки миров (функция + CLI `--all`,
  guard всех БД, диагностика срабатываний); ADDED — реестр миров `data/worlds/`;
  ADDED — побитовое совпадение прогрева (дни 1–30) всех веток сетки; ADDED —
  тень-прогнозы в `forecasts` БД ветки (граница записи = окно активации);
  MODIFIED — требование «Реестр веток и функция генерации» (guard артефактов
  обоих семейств у любой ветки, тень — часть формата мира); MODIFIED — требование
  «Побитовая повторяемость ветки» (расширено на таблицу `forecasts`).

## Impact

- Код: `simulator/policy.py` (тень-прогнозист), новый `simulator/policy_calibration.py`
  (процедура + CLI), `simulator/branches.py` (сетка `--all`, реестр миров, тень в
  `generate_branch`), `storage/repo.py::insert_forecasts` — чтение/переиспользование
  без правок схемы (PK `forecasts` с `model_version` уже подходит — §3 плана).
- Данные/артефакты: `config.yaml` (значения `policy.shift` после калибровки),
  генерируемые `artifacts/policy-calibration.json`, `data/worlds/{a-base,
  b-reactive, c-mlp, d-lstm}.db`; `data/m3_epoch.db` и каталоги `artifacts/mlp-v1-*`,
  `lstm-v1-*` — только чтение (§2 плана: не трогаем).
- Тесты: `tests/test_sim_policy.py`, `tests/test_sim_branches.py`, новый файл
  калибровки; фабрика мини-артефактов тестов `ml/` — переиспользование.
- Зависимости: новых нет (стек уже установленный).
- Следующие change'ы едят артефакты этого: `m6-worlds-ui` (реестр миров → сервер),
  `m6-compare-tab` (БД веток + тень-прогнозы).
