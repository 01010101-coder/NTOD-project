## Purpose

Воспроизводимая среда разработки проекта «taxi-demand-forecast»: установка проекта и dev-инструментов одной командой, единые цели Makefile для проверки и форматирования, импортируемые пакеты-скелеты вехи M1 и отсутствие генерируемых файлов (БД, экспорт, отчёты) в git.

## ADDED Requirements

### Requirement: Установка одной командой

Проект SHALL устанавливаться вместе с зависимостями (`numpy`, `pandas`, `pydantic>=2`, `PyYAML`) и dev-зависимостями extras `[dev]` (`pytest`, `ruff`) командой `make install`; повторный запуск SHALL проходить без ошибок (идемпотентность).

#### Scenario: Установка в окружение проекта

- **WHEN** разработчик выполняет `make install` в корне проекта
- **THEN** команда завершается с кодом 0, пакет `taxi-demand-forecast` и зависимости импортируются

#### Scenario: Повторная установка

- **WHEN** `make install` выполняется второй раз в уже установленном окружении
- **THEN** команда завершается с кодом 0 без ручных действий

### Requirement: Импортируемость пакетов-скелетов

После установки пакеты верхнего уровня `common`, `storage`, `simulator` SHALL импортироваться интерпретатором проекта; `simulator` MAY быть пустым пакетом (заполняется в M2).

#### Scenario: Импорт скелетов

- **WHEN** выполняется `python -c "import common, storage, simulator"` в окружении проекта
- **THEN** команда завершается с кодом 0, ни один пакет не выдаёт ошибку импорта

### Requirement: Цели Makefile для проверки и форматирования

Makefile SHALL предоставлять цели: `install` (установка), `test` (pytest), `lint` (ruff check + проверка форматирования), `fmt` (автоформатирование). `make lint` SHALL падать с ненулевым кодом при любом нарушении правил или несовпадении форматирования и SHALL проходить на кодовой базе после `make fmt`.

#### Scenario: Lint на чистой кодовой базе

- **WHEN** выполняется `make lint` на кодовой базе вехи M1 (пустые пакеты-скелеты)
- **THEN** команда завершается с кодом 0 без замечаний

#### Scenario: Lint на нарушении

- **WHEN** в любой модуль проекта добавлен код, нарушающий правила ruff (например, неиспользуемый импорт)
- **THEN** `make lint` завершается с ненулевым кодом и указывает файл и правило

#### Scenario: Тесты запускаются

- **WHEN** выполняется `make test`
- **THEN** pytest запускается и завершается с кодом 0 на текущей кодовой базе

### Requirement: Генерируемые файлы вне git

`.gitignore` SHALL покрывать каталоги `data/`, `reports/`, `artifacts/` и базы SQLite, чтобы БД, CSV-экспорт, графики и артефакты моделей не попадали в репозиторий.

#### Scenario: Проверка покрытия .gitignore

- **WHEN** выполняется `git check-ignore data/taxi.db reports/plot.png artifacts/model.pkl` из корня проекта
- **THEN** все три пути игнорируются; `git status` их не показывает
