## Context

Серверная линия применена и верифицирована: `web-replay-server` даёт WS-протокол (`state`/`snapshot`/`records`/`log-extended`, команды `play`/`pause`/`speed`/`seek`), REST `/api/city` (зоны с map-координатами, дороги, матрица `routes` как последовательности зон) и `/api/metrics` (строки `zone_metrics_5min` с фильтрами), статик-каталог `app/static/` со страницей-заглушкой. Решения exploration зафиксированы: только активные машины (простой парк — счётчиками зон), движение по рёбрам дорог, слайдер времени + клик-по-графику → seek, стиль — декорированная игровая карта без OSM. Снимок сегодня не содержит `assigned_at` активных поездок и неназначенных заказов — клиент после seek не может корректно нарисовать фазу «к пассажиру» и маркеры ожидания, не duplicиру механику движка.

## Goals / Non-Goals

**Goals:**

- «Живой город» как основной экран проекта: карта с машинами по рёбрам, дефицитом, средой; переживает M3/M6 (прогнозы и ветки политики лягут поверх).
- Seek — гражданин первого класса: любая перемотка честно восстанавливает мир (снимок + поток), без клиентских аппроксимаций формул движка.
- Нулевая инфраструктура фронта: статика без сборки, vanilla JS + canvas 2D, без CDN и библиотек — оффлайн-инструмент лаборатории.

**Non-Goals:**

- Оверлей прогнозов M3 и ветвление политики M6 — будущие вехи на том же канвасе.
- Показ простаивающего парка машинами (решение exploration — счётчики зон).
- JS-юнит-инфраструктура: интерфейс принимается ручным браузерным чек-листом; автотесты — только на протокольное расширение и отдачу статики.
- Мобильная адаптация, интернационализация, библиотеки графиков.

## Decisions

1. **Протокольное расширение снимка, а не клиентские эвристики.** Для фазы «к пассажиру» нужен интервал `[assigned_at, pickup_at]`; для маркеров ожидания — множество неназначенных заказов минуты. Выводить `assigned_at` на клиенте значило бы дублировать формулу подачи (rain-коэффициент, округления `travel_minutes`) — против принципа всей линии «клиент — чистая функция времени»; реконструкция ожидания из записей ≤ t после seek невозможна в принципе (поток начинается с t+1). Поэтому `snapshot` расширяется: `assigned_at` в каждой активной поездке + список `pending_orders` (`internal_id`, `origin`, `created_at`). Данные уже есть в логе — `snapshot_at` и так проходит по записям ≤ t; расширение обратно совместимо (добавление полей), оформлено MODIFIED-дельтой `web-replay-server`. Альтернатива «маленький отдельный change протокола» отвергнута: фрагментация линии из трёх change'ов на четыре без выигрыша.

2. **Локальные сим-часы с авторитетом сервера.** Клиент держит свои часы: идут с текущей `speed` между сообщениями (плавная анимация), каждая `state`/`snapshot` синкивает позицию. Записи применяются по `from_index` идемпотентно: дубли и пропуски детектируются по ожидаемому индексу, разрыв — сигнал пересинкировать. Рендер-кадр (rAF) читает только локальное состояние: часы + применённые события; приход записей с опозданием не роняет картинку — машины доезжают по своим `dropoff_at`.

3. **Дефицит и счётчики — из потока, без опроса метрик.** 5-минутное окно зоны закрывается на клиенте счётчиками спавнов/истечений из записей + `free_by_zone` последней минуты окна; правило §3.8 — то же, что в контракте данных. Карта не зависит от `/api/metrics` (его тянут только графики), `/api/metrics` нужен реже и дозагружается инкрементально.

4. **Структура статики: три классических скрипта.** `app.js` — шина (WS, команды, часы, применение записей, хранилище мира), `map.js` — карта/машины/бейджи/дефицит, `charts.js` — графики/слайдер; `index.html` + `style.css`. Без модулей-сборки: `<script>` в порядке зависимостей, общий контракт — маленькие функции отрисовки, вызываемые из rAF-цикла `app.js`. Заменяют заглушку целиком; `data-app="city-canvas"` — новый маркер страницы (тест заглушки обновляется в этом же change).

5. **Интерполяция машины — равномерно по полилинии маршрута.** Маршрут фазы — последовательность зон `routes[i][j]`, полилиния через центры зон; позиция — доля прошедшего времени фазы, отложенная равномерно по длине полилинии. Точнее по рёбрам (вес по минутам рёбер) не делаем: скорости рёбер внутри маршрута всё равно не наблюдаются клиентом, а равномерность по длине визуально честна и тривиальна.

6. **Seek-UX: троттлинг и подтверждённый рендер.** Драг слайдера шлёт `seek` не чаще ~200 мс на ближайшую минуту; мир перестраивается только по пришедшему `snapshot` (рендер из подтверждённого состояния), локальный прогноз не рисуется. Клик по графику — `seek` к `ts` окна без троттлинга (одиночное событие).

7. **Графики — самописный canvas-рендер.** Линии пяти рядов по выбранной зоне, дефицитная штриховка фона окон, вертикальный курсор playhead (по локальным часам), ось времени — весь заполненный диапазон. Дозагрузка `/api/metrics?zone=Z&from=<последний ts>` по `log-extended` с троттлом ~1 Гц. Клик маппится в индекс окна → seek. Библиотеки (chart.js и пр.) требуют CDN/сборку — исключено оффлайн-характером инструмента.

8. **Вспышки истечений — клиентский TTL.** Истечение добавляет (зона, t) в короткий список, живущий ~5 сим-минут по локальным часам и чистящийся в кадре; никаких изменений протокола.

## Risks / Trade-offs

- [Рассинхрон локальных часов с сервером при лагах сети] → сверка на каждом `state`; при расхождении > минуты — жёсткий синкинг к серверу (видимый скачок допускается, лучше честности «гладкого вранья»); пауза/seek — всегда сервер-авторитетны.
- [Шквал seek при драге] → троттл ~200 мс + рендер только по `snapshot`; серверный зажим seek в заполненный диапазон уже гарантирует корректность ответа.
- [Полный рефetch метрик на 30 дней тяжёл (8 640 строк на зону)] → инкрементальная дозагрузка от последнего ts + троттл; полная перезагрузка только при смене выбранной зоны.
- [Пачки records при 600× опережают применение] → применение батчевое по `from_index` (O(пачки)), отрисовка 6 зон + ≤ ~140 машин на кадр — тривиально для canvas.
- [Заглушка и её тест уходят одновременно] → `test_static_page` обновляется в этом же change на маркер `city-canvas`; других потребителей заглушки нет.

## Migration Plan

Аддитивно с одной заменой: снимок получает поля (обратно совместимо), статика заглушки заменяется интерфейсом (потребитель — приёмка сервера — переходит на новый экран, тест обновлён). Откат: вернуть заглушку из git, снять поля снимка — клиенты старого формата не затронуты (поля добавочные).
