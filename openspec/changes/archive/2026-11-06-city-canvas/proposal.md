## Why

Серверная линия готова: `live-engine` отдаёт поминутный поток событий, `replay-server` даёт лог, WS-управление, REST города и метрик, страницу-заглушку. Нет главного — самой визуализации «живого города»: пользователь видит страницу-заглушку, а не город. `city-canvas` замыкает тройку: игровая карта города на canvas с активными машинами, дефицитом и средой, слайдер времени и графики метрик с переходом по клику — интерфейс, который переживёт будущие вехи (на тот же канвас лягут прогнозы M3 и ветки политики M6).

## What Changes

- **Протокольное расширение снимка** (`web-replay-server`, MODIFIED): `snapshot` догоняется до полной картины минуты для честного seek — каждая активная поездка получает `assigned_at` (фаза «к пассажиру» анимируется без дублирования формул движка), плюс список `pending_orders` (неназначенные заказы минуты: `internal_id`, `origin`, `created_at`) — иначе маркеры ожидания теряются после перемотки. Реализация: `snapshot_at`/`snapshot_payload` + тесты.
- **Новая capability `web-city-ui`** — страница `app/static/` заменяет заглушку (статика без сборки, vanilla JS + canvas 2D, без внешних библиотек и CDN):
  - **карта**: зоны по map-координатам `/api/city`, дороги-рёбра, игровые декорации (стиль владельца: без OSM, декорированная top-down карта); бейдж зоны — счётчик свободных машин, при тарифе ≠ 1 — `×N`; дефицитная кайма зоны по правилу §3.8, вычисляемому из потока записей (spawns/истечения окна + `free_by_zone` последней минуты);
  - **активные машины** (только to_pickup и on_trip — решение exploration): позиции — интерполяция по маршруту из рёбер (`routes`) в фазах `[assigned_at, pickup_at]` (зона водителя → зона посадки) и `[pickup_at, dropoff_at]` (посадка → высадка); состав восстанавливается снимком после подключения/seek и ведётся потоком записей;
  - **заказы**: неназначенные — пульсирующие маркеры зоны происхождения; истечение — красная вспышка;
  - **слайдер времени** внизу: весь заполненный диапазон лога (растёт по `log-extended`), драг и клик → `seek`; текущая позиция отмечена;
  - **графики метрик** (`/api/metrics`): линии requests/completed/unfulfilled/free_drivers/тарифа по выбранной зоне, дефицитная штриховка фона, курсор playhead, дозагрузка по мере роста лога; **клик по точке → seek** к началу этого 5-минутного окна;
  - **среда и управление**: сим-часы и день недели, дождь, бейджи событий (surge — по тарифу зоны, «пятничный вечер» — по метке события метрик), play/pause, скорость.
- Тест `test_static_page` обновляется вместе со страницей (маркер заглушки заменяется маркером новой страницы).

Не меняется: механика мира, лог и его формат записей, команды/сообщения WS кроме расширения снимка, REST-контракты, конфигурация, сборка отсутствует как класс.

## Capabilities

### New Capabilities

- `web-city-ui`: браузерный «живой город» — canvas-карта с активными машинами по рёбрам, маркерами ожидания/истечений, дефицитной подсветкой и бейджами среды; слайдер времени поверх заполненного диапазона лога; графики метрик с кликом-переходом; управление воспроизведением. Клиент — чистая функция сим-времени: локальные часы идут с установленной скоростью, записи применяются по индексу, снимок восстанавливает мир после seek.

### Modified Capabilities

- `web-replay-server`: требование «WebSocket-протокол воспроизведения» — снимок минуты расширяется полями `assigned_at` активных поездок и списком `pending_orders` (неназначенные заказы с моментом создания); остальное поведение требования не меняется.

## Impact

- Файлы: правки `app/replay.py` (`snapshot_at`), `app/server.py` (`snapshot_payload`), `tests/test_web_server.py` (снимок + маркер страницы); полная замена `app/static/` (`index.html`, `style.css`, `app.js`, `map.js`, `charts.js` — заглушка уходит). Новые тесты протокольного расширения — в `tests/test_web_server.py`; интерфейс принимается ручным браузерным smoke (JS-инфраструктуры тестов в проекте нет, новые зависимости не вводятся).
- Зависимости: `replay-server` — обязательная, причём **применять после его архивации** (MODIFIED-дельта ложится на главную спеку `web-replay-server`, создающуюся при архивации); `live-engine` — транзитивно.
- Обратная совместимость: расширение снимка обратно совместимо (добавление полей); страница-заглушка намеренно заменяется — её единственный потребитель (приёмка сервера) уходит вместе с ней, тест обновляется в этом же change.
- Потребители будущего: M3 — оверлей прогнозов на зонах/графиках; M6 — ветки политики A/B на том же канвасе; решение «только активные машины» оставляет простаивающий парк счётчиками зон (данные для этого уже в потоке).
- Не входит: оверлей прогнозов и ветвление (M3/M6), мобильная адаптация, интернационализация, библиотеки графиков (самописный canvas-рендер — оффлайн-инструмент без сборки).
