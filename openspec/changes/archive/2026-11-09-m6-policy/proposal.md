# Proposal: m6-policy

## Why

Вехе M5+M6 «Лаборатория политик» (план `docs/plan-m5-m6-policy.md`, change 2 из §7)
нужны «ценовые мозги» веток: ступенчатая политика по прогнозу дефицита (C/D) и
реактивная по факту (B), встроенные в живой прогон движка. Сейчас их нечем
собрать: шов `price_fn` есть (§10.13 M2), но (а) числа ступеней негде жить —
секции `policy:` в конфиге нет; (б) признаковый слой M3 (`ml/dataset`) умеет
читать историю только из записанной БД (`SqliteRowSource`) — поверх тикающего
движка источника нет, а без него прогноз `deficit_prob` в контуре не из чего
собрать; (в) композиция тарифа не определена — подмена тарифа политикой ломала
бы сравнение с миром (политика в дождь делала бы ветку дешевле базовой, решение
6 вехи). Без этого change'а генератор веток (`m6-rng-branches`) не может
воспроизвести ничего, кроме мира без политики.

## What Changes

- **Секция `policy:` в `config.yaml`** (прил. А плана): `horizon_min: 15`,
  `stairs` [{p_min 0.40 → ×1.15}, {0.60 → ×1.30}, {0.80 → ×1.50}],
  `total_cap: 2.0`, `reactive_mult: 1.30`, `shift: {mlp: 0.0, lstm: 0.0}`,
  `target_fire_rate: 0.10`, `worlds_dir: data/worlds` — pydantic-модель с
  дефолтами (старые конфиги грузятся), числа стартовые, калибруются в
  `m6-worlds`.
- **Ступенчатая политика**: `p_eff = clip(deficit_prob + shift[model], 0, 1)`;
  множитель — верхняя ступень с `p_min ≤ p_eff`, ниже всех ступеней ×1.00.
  Горизонт один на обе модели (`horizon_min`, ожидаемо 15 — лучший test-F1,
  фиксируется до генерации веток).
- **Композиция умножением, не подменой** (решение 6): итоговый тариф зоны =
  `min(тариф_мира(t) × множитель, total_cap)`; при неактивной политике
  (множитель 1.00) тариф мира возвращается без изменений — дни 1–30 ветки
  побитово равны `a-base`.
- **Ветка B «реактивная»** (анти-пример ТЗ): дефицит в зоне сейчас (последний
  закрытый бакет, правило контракта) → `reactive_mult`, иначе ×1.00; без
  прогноза и упреждения.
- **`LiveRowSource`** — реализация протокола `RowSource` (`ml/dataset`) поверх
  живого движка: метрики бакетов — из нового чистого шва наблюдения
  `on_metrics_row` (строки `AggregateBuffer` на закрытии бакета), расписание
  высадок — из событий назначений существующего `on_minute`.
- **Контур инференса из артефактов M3 без ретрейна**: на каждый закрытый бакет
  тест-недели — окно признаков `build_window` над `LiveRowSource` (те же
  анти-лик гарантии, что в M3) → `deficit_prob` из артефакта модели
  (`load_model_artifact`) → ступени → `price_fn`. Прогноз кэшируется на бакет.
- **Реестр веток**: запись `b-reactive` / `c-mlp` / `d-lstm` в `BRANCHES`
  (`simulator/branches.py`) как фабрики контура политики (спека
  `simulator-branches` прямо называет `m6-policy` подключателем веток);
  `generate_branch` привязывает контур к движку и передаёт его наблюдатели в
  `run`.
- **Тесты**: юнит-тесты на стаб-модели (фиксированный p → ожидаемый множитель);
  эквивалентность `LiveRowSource` ↔ `SqliteRowSource` одного прогона; анти-лик
  контура; инертность политики до тест-недели; побитовый детерминизм ветки с
  контуром.

Не входит (последующие changes вехи): δ-калибровка `shift` и
`artifacts/policy-calibration.json`, генерация сетки A/B/C/D с тень-прогнозами
и автотест побитового совпадения дней 1–30 (`m6-worlds`); реестр миров в
сервере, переключатель, тумблер факт/прогноз, бейдж тарифа, seek-связка
(`m6-worlds-ui`); вкладка «Сравнение» (`m6-compare-tab`). Ретрейн моделей,
Platt/изотонная калибровка, гистерезис ступеней, новые зависимости — запрещено
планом (§2).

## Capabilities

### New Capabilities

- `simulator-policy`: ценовые политики вехи M5+M6 — секция `policy:` конфига с
  дефолтами прил. А, ступенчатая политика по `p_eff` со сдвигом `shift[model]`,
  реактивное правило ветки B, композиция с тарифом мира умножением с потолком
  `total_cap`, `LiveRowSource` поверх живого движка, контур инференса из
  артефактов M3 (без ретрейна), окно активации (дни 31–37), анти-лик и
  детерминизм контура.

### Modified Capabilities

- `simulator-loop`: требование «Агрегация zone_metrics_5min» — новый
  опциональный чистый шов наблюдения `on_metrics_row(row)` у `Engine.run`
  (строка метрик на закрытии каждого бакета, наблюдение не меняет таблицы и не
  тратит rng); требование «Шов price_fn для A/B-экспериментов» — движок
  дополнительно предоставляет публичное чтение тарифа мира
  `world_tariff(zone_id, t)` для политик, компонующих тариф умножением.
- `simulator-branches`: требование «Реестр веток и функция генерации» — в
  реестре появляются ветки `b-reactive`/`c-mlp`/`d-lstm`; правило ветки —
  фабрика контура политики, получающая конфиг и движок (тариф мира +
  наблюдатели); `generate_branch` строит контур, подключает его как
  `price_fn` и передаёт наблюдателей контура в `run`.

## Impact

- Затронутые модули: `common/config.py` (модель `PolicyCfg` + поле корня),
  `config.yaml` (секция `policy:`), `simulator/engine.py` (шов
  `on_metrics_row`, чтение `world_tariff` — ~15 строк), `simulator/branches.py`
  (реестр b/c/d + привязка контура), новый `simulator/policy.py` (ступени,
  реактивное правило, композиция, `LiveRowSource`, контур), новые тесты
  `tests/test_sim_policy.py`.
- Переиспользуются без изменений: `ml/dataset.build_window` и протокол
  `RowSource` (анти-лик семантика наследуется), `ml/infer.load_model_artifact`
  и `latest_artifact_dir` (снимок `ml_cfg` из артефакта — защита от дрейфа
  конфига), `simulator/live.MinuteRecord` (события назначений).
- Спецификации: дельты `specs/simulator-policy/spec.md` (ADDED),
  `specs/simulator-loop/spec.md` (MODIFIED ×2), `specs/simulator-branches/spec.md`
  (MODIFIED). `ml-dataset`/`ml-inference`/`simulator-live` не меняются — контур
  потребляет их публичные контракты как есть.
- Совместимость: CLI `simulator.branches` без изменений аргументов; `a-base` и
  прогоны без политики не меняются (`on_metrics_row=None` — поведение как до
  change'а); эталонные БД и артефакты M3 не трогаются. Новых зависимостей нет.
- Приёмка: `make lint && make test`; замер накладных расходов контура
  (риск §8.5) на коротком прогоне с реальными артефактами; счётчик срабатываний
  ступеней доступен для будущей δ-калибровки (`m6-worlds`).
