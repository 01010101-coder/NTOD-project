## Why

Веб-визуализация «живой город» (первый из трёх change'ов интерфейсной линии: за ним идут `replay-server` и `city-canvas`) требует поминутной детализации мира, которой нет в SQLite: таблицы хранят только терминальные состояния `trips` и 5-минутные агрегаты. Зона водителя в момент назначения, моменты посадки/высадки активных поездок, поминутный тариф и дождь, счётчики свободного парка по зонам — из БД не восстановимы. Контракт детерминизма `simulator-loop` (один seed → побайтово те же таблицы) делает повторный прогон точным воспроизведением записанной истории — движку не хватает только шва наблюдения, чтобы отдать эту детализацию наружу, не меняя сам мир.

## What Changes

- Новый модуль `simulator/live.py` — иммутабельные типы событийного потока наблюдения: `MinuteRecord` (сим-минута `t`, `is_rain`, фактический тариф по зонам, `free_by_zone`, события минуты `spawns`/`assignments`/`dropoffs`/`expiries`) и события `SpawnEvent`, `AssignEvent`, `DropoffEvent`, `ExpiryEvent`. События несут всё, что нужно клиенту для анимации без знания механики: назначение — зону водителя в момент назначения и моменты `pickup_at`/`dropoff_at`; внутренний id заказа — сквозная нить «спавн → назначение → терминальное событие».
- `Engine.run(..., on_minute=None)` — опциональный колбэк-наблюдатель: запись после каждой обработанной сим-минуты (включая минуты дренажа хвоста после основной фазы). Наблюдение — чистое чтение состояния мира: rng не тратится, порядок разыгрываний, строки таблиц и `Summary` не меняются; при `on_minute=None` поведение движка и накладные расходы — как до change'а.
- Гарантия чистоты наблюдения — тестом: прогоны с наблюдателем и без на одном seed дают побайтово идентичные `trips` и `zone_metrics_5min`; два прогона с наблюдателем дают одинаковые последовательности записей.
- Новые тесты `tests/test_sim_live.py`: чистота наблюдения (идентичность таблиц), сверка потока с таблицами (каждой строке `trips` соответствует цепочка событий с согласованными временами и зонами), детерминизм записей, записи дренажа.

Не меняется: механика мира (среда/спавн/диспатч/движение/истечения), формат БД и писатель `TripWriter`, агрегация `zone_metrics_5min`, CLI `python -m simulator`, сигнатуры существующих вызовов `Engine.run` (параметр только опциональный).

## Capabilities

### New Capabilities

- `simulator-live`: шов наблюдения движка — поминутный событийный поток `MinuteRecord` через `on_minute` у `Engine.run`: состав и семантика полей записи и событий минуты (включая дренаж хвоста), инвариант чистоты наблюдения (наблюдатель не меняет таблицы и поток rng, события детерминированы на одном seed).

### Modified Capabilities

(нет — требования `simulator-loop` не меняются: `Engine.run(days, writer, *, progress=None)` возвращает `Summary` как и раньше, детерминизм, агрегация и CLI не затронуты; `simulator-live` лишь расширяет контракт движка опциональным параметром)

## Impact

- Файлы: новый `simulator/live.py`, правка `simulator/engine.py` (сбор событий минуты + вызов колбэка), новый `tests/test_sim_live.py`. Не трогаются: `simulator/__main__.py`, `simulator/{city,demand,drivers,env,aggregate,calibrate}.py`, `common/`, `storage/`, `config.yaml`, `Makefile`, существующие тесты.
- Зависимости: нет новых — только stdlib/numpy и существующий публичный API `Fleet.free_by_zone`/`busy_by_zone`, `WorldEnv.is_rain`; для `price_fn`-прогонов тариф в записи — фактический (`_tariff_mult`), без отдельной обработки.
- Потребители: будущий `replay-server` — тихий прогон движка с `on_minute` строит событийный лог (основа «машины времени»: seek в обе стороны чтением лога); `city-canvas` — клиент анимируется событиями как чистая функция сим-времени (решение «только активные машины»: активные восстанавливаются из `assignments`/`dropoffs`, простой парк — счётчиками зон, поэтому по-водительный снапшот парка не нужен).
- Накладные расходы: сбор записей выполняется только при заданном колбэке; бюджет A4 (30 дней ≤ 60 s) проверяется на CLI без наблюдателя и не меняется.
- Не входит (scope следующих change'ов): событийный лог и его хранение, FastAPI/WS/REST, реконструкция маршрутов next-hop Флойда, обновление устаревшей строки про Streamlit в `openspec/config.yaml` — всё это `replay-server`; отрисовка карты и слайдер — `city-canvas`.
