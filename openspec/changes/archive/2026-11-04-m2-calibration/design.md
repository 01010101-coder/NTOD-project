## Context

`m2-loop` закрыт и в архиве: движок, агрегат §3.8, CLI §4, дословный скрипт приёмки и Makefile-цели работают; гейт `make accept-m2` — A1–A12 зелёные, единственный провал A13 (exit 1). Заготовка `simulator/calibrate.py` уже умеет прогонять мир и печатать одну машинную строку `deficit_share=<X>%` (по приватному предикату `simulator.aggregate._is_deficit`); стартовый замер на эталоне (30 дней, seed 42, `base_rate` 2.0, парк 200): `deficit_share=67.3%` — мир «всё красное», цели §9 не достигнуты. Состав `simulator/` — ровно 9 файлов приложения Б (A3), pandas/matplotlib в пакете пока не подключены (заготовке не были нужны; разрешены только в `calibrate.py` — §2.2 п. 2). Каталога `reports/` и отчёта `docs/m2-calibration.md` не существует. `config.yaml` = приложение А дословно (числа — стартовая точка; прил. А: «финальные фиксируются калибровкой (`m2-calibration`) и обновляются здесь же и в `config.yaml`»). Существенные разделы плана: §9, §11.2, приложение А, запреты §2.2; критерий A13 — `simulator.calibrate` exit 0, `deficit_share=<X>%` с X ∈ [10, 20], ≥ 3 PNG в `reports/`, `docs/m2-calibration.md` содержит `deficit_share=`. Гейт сдачи: `make accept-m2` полностью зелёный (A1–A13, exit 0) — §7.

## Goals / Non-Goals

**Goals:**

- `simulator/calibrate.py` — полный инструмент §9: прогон 30 дней, три названных графика (суточный профиль по зонам, ряд с дождём, гистограмма `free_drivers` — ≥ 3 PNG в `reports/`), машинная строка `deficit_share=<X>%` без изменений формата.
- Откалиброванный эталон по целям §9: дефицитные 5-минутки 10–20 %; суточная волна читается глазами; дождь и пятница дают различимые горбы; средняя занятость парка ~60–70 %, пиковая ~90 %+.
- Финальные числа в `config.yaml`; отчёт `docs/m2-calibration.md` (какие числа, почему, графики, то же число `deficit_share=`).
- Гейт: `make accept-m2` — все A1–A13 PASS, exit 0; остаются только ручные пункты §11.2.

**Non-Goals:**

- Автотюнер/оптимизатор калибровки, новые модули, новые ключи конфига (запрет §2.2 пп. 1, 5–6: подбор — ручные итерации по четырём ручкам §9: `base_rate`, профили, `drivers.count`, `dest_decay_min`; `population.scale` и прочие ключи — не ручки калибровки).
- Правки движка/агрегата/CLI/скрипта приёмки/Makefile (скрипт правится только вместе с планом — §11.1); новые обязательные тесты (строка №6 §7 тестов не называет; приложение Б: `calibrate.py` — «только smoke, если удобно»).
- Заполнение `forecasts`, изменения `common/`/`storage/` вне оговоренного открытого вопроса 1 (proposal) — M3.

## Decisions

### 1. Заготовка — фундамент: докрутка только графиками и отчётностью, формат вывода не меняется

`argparse` (`--days`, дефолт 30; `--seed`, дефолт None → из конфига), внутренний writer метрик и печать `deficit_share=<X>%` (`f"deficit_share={share:.1f}%"`) сохраняются как есть — их уже проверяет A13 (sed берёт последнее вхождение `[0-9][0-9.]+`; держим ровно одну машинную строку, как у заготовки). Докупается: каталог `reports/` (`mkdir` при запуске) и три matplotlib-PNG. matplotlib с headless-бэкендом: `matplotlib.use("Agg")` до импорта pyplot — команда должна работать без дисплея (CI/ssh). pandas — только для сводов метрик прогона (почасовые/посуточные группировки), matplotlib — только для PNG: оба разрешены исключительно в этом файле (§2.2 п. 2). Прогон движка не меняется: один прогон на команду, seed/`sim_start` из конфига, wall-clock — только для отчётности (§5). Альтернатива «отдельный быстрый симулятор для итераций подбора» отвергнута — дублирование мира запрещено §2.2 п. 1; итерации подбора гоняются тем же CLI с меньшим `--days` (скорость), финальная проверка — 30 дней, seed 42 (A13).

### 2. Графики: данные из метрик того же прогона, три названных PNG

Все три графика строятся из строк `zone_metrics_5min` (и, при нужде, `requests`-счётчиков) единственного прогона команды — калибровка не запускает мир дважды:

- **Суточный профиль по зонам** — средний почасовой профиль заказов (`requests`) по каждой зоне (6 линий); будни и выходные отдельно, чтобы читались волна §3.1 (утренний отток residential, вечерний магнит business/mixed) и «пятничный вечер» (горб 17–23 у business/mixed); способ показать пятницу (отдельная кривая/панель) — деталь исполнителя, требование — различимость горбов (§11.2 п. 2).
- **Ряд с дождём** — временной ряд по городу (например, почасовые `requests` или доля дефицитных окон) с выделением дождливых окон (`is_rain`): эпизоды дождя (спрос ×1.4, время ×1.4 — §3.6) должны читаться как горбы/провалы относительно сухих.
- **Гистограмма `free_drivers`** — распределение снапшотов `free_drivers` по всем окнам и зонам: видно, что парк «есть, но впритык» (цель §9), хвост малых значений соотносится с 10–20 % дефицитных окон.

Имена PNG-файлов — деталь исполнителя (A13 считает только `ls reports/*.png | wc -l` ≥ 3); предложить: `reports/daily_profile.png`, `reports/rain_series.png`, `reports/free_drivers_hist.png`. Альтернатива «генерировать графики в каталог `--out`» отвергнута — §9 фиксирует `reports/`, аргумент не назван ни планом, ни A13.

### 3. Подбор: ручные итерации по четырём ручкам §9, старт 67.3 % дефицита

Процедура: прогон → `deficit_share`/занятость/графики → правка чисел в `config.yaml` → повтор; ожидаемо 3–6 итераций (итерации допустимо гонять на `--days 7` для скорости, финал — всегда 30 дней seed 42). Направления из старта (67,3 % — парка не хватает): поднять `drivers.count` и/или снизить `base_rate`; `dest_decay_min` локализует спрос `P(B|A) ∝ attract_dest(B) × exp(−path_min/dest_decay_min)` — большие значения распределяют спрос ровнее, малые концентрируют у магнитов (center/lounge) и плодят локальные дефициты; профили (24×2 на архетип) правятся, если волна/горбы читаются плохо (сгладить ночные ямы, подчеркнуть часы 17–23). Занятость парка считается по снапшотам окон: `busy/(busy+free)` — средняя по всем снапшотам ~60–70 %, пиковая (верхняя перцентиль, например p95 по окнам города) ~90 %+; формула фиксируется в отчёте (план занятость числом не задаёт — это ориентир §9, проверяется глазами заказчиком §11.2). На каждой итерации контролируются A-инварианты, которых числа могут сломать: A5 (есть и `completed`, и `unfulfilled` — при 10–20 % дефицита выполняется с запасом, но проверять), A4 (`wall ≤ 60 с` — больше парка = больше работы диспатча), A11 (канон: `base_rate > 0`, 4 архетипа 24×2, множители > 1, `day_chance ∈ (0, 1]`). Итог итераций — числа строго в `config.yaml`, никакого подгона в коде (запрет §2.2 п. 6; магические числа мира в `calibrate.py` запрещены).

### 4. Финальные числа: config.yaml + синхронизация дефолтов и пинов теста канона (рабочее решение открытого вопроса 1)

Числа вносятся в `config.yaml`. `tests/test_sim_city.py:61–63` требует `load_config(config.yaml) == AppConfig()` — если править только `config.yaml`, A2 (`make test`) падает и «полностью зелёная» приёмка недостижима. Рабочее решение (до ответа заказчика — proposal, вопрос 1): синхронно правятся дефолты `common/config.py` для тех же ручек (комментарий `config.yaml` от `m2-city` прямо это предусматривает: «финальные… обновляются здесь же и в дефолтах моделей `common/config.py`») и запиненные скаляры `test_config_defaults_match_canon_a11` (`tests/test_sim_city.py:96–102`: `base_rate == 2.0`, `drivers.count == 200`, `wait_limit_min == 6` — правятся только тронутые калибровкой), структурные проверки тестов не меняются; `tests/test_config.py` пинит только `seed`/`db_path` — они калибровкой не трогаются. Прочие эффекты смены чисел перевычисляются гейтом и ничего в коде не требуют: A7 (хэши детерминизма не зафиксированы в тестах), `test_reproducibility` (сравнивает два прогона между собой, не с эталоном), A5/A6 (инварианты структуры), A11 (неравенства). Альтернатива «выбрать числа, не трогающие запиненные скаляры (только профили/`dest_decay_min`)» отвергнута как ограничение ручек §9 задним числом: подбор обязан быть свободным по всем четырём, а не подгоняться под список пинов.

### 5. Отчёт docs/m2-calibration.md: методика, итерации, финальные числа, графики

Структура (§9 «какие числа, почему, графики» + §11.2 п. 2): цель калибровки (§9 дословно: коридор дефицита, волна, горбы, занятость); методика (прогон 30 дней seed 42, `deficit_share` по правилу §3.8, занятость по снапшотам, ручки); таблица итераций (вариант → ручки → `deficit_share`/занятость → вывод); финальные числа таблицей «было → стало» с обоснованием каждого; графики `reports/*.png` с пояснением, где смотреть (утренний отток residential / вечерний магнит center; горб «пятницы» 17–23 у business/mixed; дождевые эпизоды на ряде; хвост гистограммы); строка `deficit_share=<X>%` — то же число, что печатает калибровка (A13 grep по файлу); назначение — эталон мира для M3. Файл на русском; единственный машинный контракт — наличие подстроки `deficit_share=`.

### 6. Границы: скрипт приёмки, Makefile и состав пакета не трогаются

`scripts/accept_m2.sh` — дословно приложение В, не правится (§11.1); Makefile не меняется; `simulator/` остаётся ровно 9 файлов приложения Б (A3); новые тесты не добавляются — A13 проверяет всё поведение калибровки скриптом, ручные проверки §11.2 — заказчиком. Список правок change'а: `simulator/calibrate.py`, `config.yaml`, `docs/m2-calibration.md`, `reports/*.png` (+, по рабочему решению вопроса 1, дефолты `common/config.py` и тронутые пины `tests/test_sim_city.py`).

## Risks / Trade-offs

- [Финальный подбор требует изменения запиненных скаляров (`base_rate`, `drivers.count`)] → рабочее решение реш. 4 (синхронно дефолты + пины теста); старт 67,3 % дефицита делает «не трогать парк/base_rate» маловероятным. Если заказчик ответит «только config.yaml» — переделка реш. 4 и задач через `openspec-update-change` (правка теста равенства вместо правки дефолтов).
- [wall после подбора > 60 с (A4)] → на каждой итерации смотреть `wall_sec`; бюджет проверяется гейтом на финальных числах. Резерв §5 (векторизация пуассонов) уже потрачен/зафиксирован детерминизмом `m2-loop` — новая векторизация = правка мира = новый design, не молчаливая правка.
- [Мир «позеленеет» слишком сильно: `unfulfilled = 0` → A5 FAIL] → цель §9 — 10–20 %, обе стороны коридора проверяются на каждой итерации; A13 принимает только X ∈ [10, 20].
- [«Волна/горбы читаются глазами» — субъективный критерий] → §11.2 п. 2 — ручная проверка заказчика, скриптом не заменяется; отчёт прикладывает PNG и указывает, где именно смотреть (часы/архетипы).
- [matplotlib в окружении без дисплея] → Agg-бэкенд до импорта pyplot (реш. 1); зависимость уже заявлена проекту (openspec/config.yaml: «matplotlib для отладочных графиков») и pyproject dev-зависимостям не противоречит — проверить наличие в `.venv` на первой итерации.
- [Долгие итерации подбора: 30-дневный прогон ~40–60 с] → итерации на `--days 7`, финал на 30 днях (реш. 1); скрипт приёмки сам прогоняет калибровку ещё раз (~2–4 мин на полный гейт — заявлено прил. В).

## Migration Plan

Правки локальны: докрутка `simulator/calibrate.py`, числа в `config.yaml` (+ синхронные дефолты/пины по реш. 4), новые `docs/m2-calibration.md` и `reports/*.png`. Схема SQLite, скрипт приёмки, Makefile, состав пакета не меняются; откат — git-откат правок и удаление новых файлов. Смена чисел меняет мир (другая история при том же seed) — это ожидаемо: детерминизм A7 перевычисляется гейтом, зависимости M3 читают откалиброванный мир. `data/`-артефакты прогонов (`taxi.db`, `accept-*.db`) чистятся скриптом приёмки; `reports/` и отчёт коммитятся как результаты вехи.
