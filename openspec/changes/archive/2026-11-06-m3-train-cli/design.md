## Context

`ml-dataset`, `ml-baselines`, `ml-model` заархивированы: есть источники строк
и сборка примеров по ролям дней (`ml.dataset`: `SqliteRowSource`,
`collect_examples`, `DatasetScalers`, `world_start`), архитектуры с loss и
seed (`ml.model`: `build_model`, `MultitaskLoss`, `deficit_pos_weight`,
`set_global_seed`), наивы и метрики. Секция `ml:` конфига уже несёт все
гиперпараметры обучения (приложение А плана M3), `make epoch` генерирует БД
эпохи. Недостающее — цикл обучения, CLI, артефакты. Формат артефактов здесь
становится контрактом для `m3-inference` (восстановление сети) и `m3-ml-tab`
(кривая loss), поэтому фиксируется в этом design.

## Goals / Non-Goals

**Goals:**

- Обучение `mlp`/`lstm`/`both` одной командой с ранней остановкой и
  seed-детерминизмом; артефакты, читаемые без живого конфига.
- Экспериментальное подтверждение дефолта окна (свип 3/6/12 на MLP) с
  фиксацией результата в `artifacts/window-sweep.json`.
- Нулевые правки существующих модулей `ml/` и конфига (кроме возможной правки
  значения `ml.window_hours` по итогам свипа — шаг задачи).

**Non-Goals:**

- Инференс/walk-forward и сводная таблица против наивов — `m3-inference`.
- Графики loss и экраны — `m3-ml-tab` (читает `loss.json`/`metrics.json`).
- GPU, новые зависимости, Makefile-цели под обучение (план зовёт CLI напрямую).
- Автоправка `config.yaml` свипом: YAML редактируется руками в задаче.

## Decisions

1. **Тонкая склейка поверх `ml/`.** `ml/train.py` не дублирует ни сборку
   примеров, ни нормализацию, ни loss: вызывает `collect_examples` →
   `DatasetScalers.fit` (train) → `transform_*` (все роли) →
   `deficit_pos_weight` → `set_global_seed` → `build_model` → `MultitaskLoss`.
   Альтернатива — цикл обучения внутри `ml/model.py` — отвергнута: модельный
   модуль остаётся чистым контрактом архитектур (его спека про это и говорит).

2. **Батчинг вручную, детерминизм из двух независимых rng.** Перестановки
   train-эпох даёт `np.random.default_rng(ml.seed)` (отдельный от
   `set_global_seed`, который отвечает за инициализацию весов и dropout);
   тензоры собираются раз в батч — прецедент «конвертация на границе
   вызывающего» (решение 6 design.md `ml-model`). `torch.utils.data.DataLoader`
   с generator не используется: третий источник случайности без выгоды при
   массивах, уже лежащих в памяти. Устройство — CPU без уточнений.

3. **Ранняя остановка.** Метрика — средний по батчам val `total` (без
   перемешивания); улучшение — строгое «меньше»; при отсутствии улучшения
   `ml.patience` эпох подряд обучение стопится; кап `ml.max_epochs`. Лучший
   state_dict хранится глубокой копией и сохраняется, даже если после него
   были эпохи (спека: «сохраняется лучшая эпоха»).

4. **Формат артефактов — контракт для `m3-inference`.** Каталог
   `artifacts/{arch}-v1-{YYYY-MM-DD, локальная дата}/`:
   - `weights.pt` — `torch.save` словаря `{arch, state_dict, ml_cfg:
     cfg.ml.model_dump()}`: инференс пересобирает сеть из снимка конфига и не
     зависит от дрейфа `config.yaml` между обучением и инференсом;
   - `scalers.pkl` — `DatasetScalers.save` в каталог модели. Scaler'ы зависят
     от `window_hours`, поэтому живут в артефакте модели; дефолтный путь
     `artifacts/dataset/scalers.pkl` (`ml-dataset`) остаётся для автономных
     нужд — обучение туда не пишет;
   - `loss.json` — список `{epoch, train: {total, mse_requests, mse_free,
     bce}, val: {…}}` по эпохам;
   - `metrics.json` — `{model_version, arch, window_hours, seed, pos_weight,
     n_train, n_val, best_epoch, best_val: {total, mse_requests, mse_free,
     bce}, ml_cfg: снимок, wall_sec}`.
   Каталог существует → отказ до начала обучения (архитектуры `both`
   проверяются все сразу), exit 2. Авто-суффикс `-2` отвергнут: молча рвёт
   связь «имя каталога = model_version» и плодит мусор.

5. **`model_version` = `{arch}-v1-{локальная дата запуска}`.** Формат плана
   M3 (§7): связывает строки `forecasts` с каталогом артефактов.

6. **Свип окна.** Подкоманда `sweep --windows 3,6,12` прогоняет ту же функцию
   обучения MLP с подменой `window_hours` (без записи каталогов моделей);
   критерий — val MAE прогноза спроса в физических заказах: прогнозы проходят
   обратное преобразование scaler'а таргетов, MAE против сырых val-таргетов,
   среднее двух горизонтов. Итог — `artifacts/window-sweep.json`
   `{windows: [{window_hours, val_mae_requests, best_val_total, best_epoch}],
   winner}` + строка победителя в stdout. Разные окна дают чуть разные
   выборки (первый обучающий ts сдвигается на длину окна) — честно: окно и
   есть настройка обучения; числа фиксируются в json для отчёта.

7. **CLI.** `python -m ml` c подкомандами `train` и `sweep` (argparse;
   `m3-inference` добавит `infer`). `train`: `--config` (дефолт
   `config.yaml`), `--arch {mlp,lstm,both}` (дефолт `both`), `--db` (override
   `ml.db`). Прогресс — по эпохам в stderr (`epoch 12/100 arch=mlp loss=…
   val=… patience_left=8`, приложение Б плана), итог — в stdout
   (`done: model_version=… artifacts=… val=…`). Ошибки (нет БД, пустая роль
   train/val, неизвестная архитектура, занятый каталог) — сообщение в stderr,
   exit 2; успех — exit 0. Пустые роли ловятся до обучения;
   вырожденная доля дефицита уже даёт понятный `ValueError` из
   `deficit_pos_weight` — CLI оборачивает в сообщение.

8. **Корень артефактов — относительный `artifacts/` от cwd.** Без флага
   `--out`: пользователь запускает из корня проекта (прецедент — `make sim`
   пишет `data/`), тесты CLI используют `monkeypatch.chdir(tmp_path)`.

## Risks / Trade-offs

- [LSTM на полной эпохе (≈48 тыс. примеров × 72 шага) медленнее MLP] →
  кап `max_epochs` + ранняя остановка уже в конфиге; по плану §5 укладывается
  в минуты на CPU; если нет — уменьшается `max_epochs` в конфиге, не
  архитектура.
- [Сравнение окон на немного разных выборках] → осознанно (решение 6);
  числа зафиксированы в `window-sweep.json` и попадут в отчёт вехи.
- [`torch.save`/pickle чувствительны к версиям torch/sklearn] → артефакты
  локальные для `.venv` проекта; roundtrip-тест читает их тем же окружением.
- [Коллизия model_version при повторе в ту же дату] → явный отказ exit 2;
  повторные прогоны (детерминизм-тест) идут в разные корни через chdir.
- [Дрейф `config.yaml` после обучения] → снимок ml-секции лежит и в
  `weights.pt`, и в `metrics.json` — восстановление и воспроизводимость не
  зависят от текущего конфига.
