# Design: m6-worlds-ui

## Context

Опора — закрытые change'ы: `m6-worlds` (сетка `data/worlds/*.db` с тень-прогнозами
обоих семейств с дня 31, реестр `list_worlds`/`WorldInfo`{name, db, label, exists},
фабрики контуров `BRANCHES`), `replay-server` (ReplayLog + фоновый `FillRun`
движка, `ReplayController(log, meta, sim_start)`, WS `state.world` = meta),
`city-canvas` (карта/surge-бейдж/слайдер/seek), `m3-ml-tab` (вкладка «Лаборатория»,
REST `/api/ml/*` читают `ml.db`). Направление зависимостей: `app` импортирует
`simulator`/`storage` публично (прецедент `replay-server`).

## Goals / Non-Goals

**Goals:** переключатель миров Эпоха/A/B/C/D; тумблер окраски факт/прогноз;
бейдж тарифа подтверждён на контурной ветке; seek-связка «Лаборатория → Город».

**Non-Goals:** вкладка «Сравнение» (change 5); тумблер горизонта прогноза
(берётся `policy.horizon_min`); окраска прогнозом в прогреве; синтез минутных
событий из БД; выбор модели прогноза отдельным селектором на карте (модель —
селектор «Лаборатории»).

## Decisions

1. **Лог мира — фоновый детерминированный прогон движка, не чтение БД.** Ветки
   побайтово воспроизводятся перезапуском с seed (§3 плана, тест m6-worlds), а БД
   не содержит минутных событий (только trips/агрегаты) — карта требует поток
   `MinuteRecord`. Прогон правила ветки уже инкапсулирован реестром
   (`BRANCHES[name]` → контур/без политики): `app` строит `Engine(cfg, seed,
   price_fn=…)` фабрикой ветки и кормит `ReplayLog` через существующий `FillRun`
   (`start_fill` обобщается источником политики; тень не поднимается — прогнозы UI
   читает из БД мира). Первый мир (по умолчанию «Эпоха») строится при старте, как
   сегодня; мир ветки — при первом выборе (лениво), логи живут до конца процесса
   (37 дней ≈ 43 тыс. записей на мир, десятки МБ — норма RAM).
   Альтернатива «синтез записей из trips» отклонена: спавны/среда/парк в БД
   поминутно отсутствуют, приблизили бы панель и бейджи.
2. **Мир «Эпоха» — прогон без политики на ту же длину (`ml.train_days +
   ml.test_days`), с честной меткой.** После rng-разделения движок побитово не
   воспроизводит `m3_epoch.db` (принято планом §3); метка мира в `state.world`
   честно говорит «прогон эпохи (rng-разделение); метрики/прогнозы „Лаборатории“ —
   из m3_epoch.db». Seek-связка прыгает по моменту времени — конфигурация мира
   одна и та же. Дней у Эпохи и веток поровну — слайдер/позиции сравнимы.
3. **Переключение мира — REST `POST /api/worlds/{name}/switch`** (не WS-команда):
   смена мира редка, REST проще тестировать; ответ = новое `state`. Сервер держит
   `ReplayController` на мир; `switch` атомарно меняет активный контроллер и
   рассылает `state`+`snapshot` всем WS-сессиям (позиция — старт мира, пауза —
   сохраняется). WS-сессии при переключении перевязываются на новый контроллер.
   Неизвестное имя/отсутствующий файл БД мира — 404/409, мир не меняется.
4. **Прогнозы мира — REST `GET /api/worlds/{name}/forecasts`** (зона/горизонт —
   параметры; горизонт по умолчанию `policy.horizon_min`): `mode=ro` к БД мира
   (для Эпохи — `ml.db`), строки тени `model_version` = `mlp`/`lstm`; для Эпохи —
   версии с артефактами (полные имена `*-v1-*`). Фронт для Эпохи берёт версию,
   выбранную в «Лаборатории», для веток — её семейство (`arch` версии): дефолт —
   лучшая по test-F1 (сводка `summary-*.json`, прецедент выбора модели вехи).
   Анти-лик: читаются только закрытые бакеты (строки пишутся на закрытие — m6-worlds).
5. **Тумблер «факт/прогноз» — клиентский режим окраски зон** (кнопка в панели
   «Города»): факт — текущее правило дефицита (как сегодня, включая прогрев);
   прогноз — дефицитная кайма зоны по `deficit_prob ≥ 0.5` ближайшего закрытого
   бакета выбранной модели (fetch прогнозов по мере воспроизведения, кэш на бакет);
   нет строки (прогрев/дыра) — нейтральная кайма. Скаляр цены/двухуровневая
   интенсивность не вводятся — бинарная кайма, как у факта.
6. **Бейдж тарифа — без переделки:** записей `price_mult` минут достаточно
   (`contour.price` → движок → `MinuteRecord.price_mult`); сценарий спеки
   закрепляет видимость множителя политики на контурной ветке (×1.15/×1.30/×1.50).
7. **Seek-связка — расширение обработчика клика лаб-графика** (прецедент клика
   городского графика): если активный мир ≠ «Эпоха» — сначала `switch` на Эпоху,
   затем `seek` на момент точки; иначе только `seek`. Промис-цепочка, одна
   пользовательская операция (§6 плана).

## Risks / Trade-offs

- **RAM пяти миров** (~5×43 тыс. записей): принято (десятки МБ); ленивость
  переключения ограничивает число одновременно живых миров пятью.
- **Прогон ветки при первом выборе занимает ~30–60 с до готовности лога**:
  как при старте сегодня — `state.filled` растёт, интерфейс честно ждёт
  (позиция уже на старте мира, seek в заполненный диапазон).
- **Эпоха ≠ m3_epoch побитово**: честная метка (решение 2), seek-связка — по
  моменту времени; отражено в отчёте вехи.
- **Прогнозная окраска на ~10 % срабатываний ступеней выглядит спокойнее факта**
  (порог 0.5 при калиброванных δ): ожидаемо и честно — частота вмешательств
  калибрована; порог окраски не подгоняется.
