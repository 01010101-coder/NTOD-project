# Proposal: m6-worlds-ui

## Why

Change 4 вехи M5+M6 (§7 плана `docs/plan-m5-m6-policy.md`): сетка миров существует
(`data/worlds/{a-base,b-reactive,c-mlp,d-lstm}.db`, change `m6-worlds`), реестр миров
доступен программно (`simulator.branches.list_worlds`) — но «Город» показывает один
мир, вкладки «Город» и «Лаборатория» формально не связаны, а карта красится только
фактическим дефицитом, тогда как ТЗ требует «красный = ожидается дефицит». Без этого
change'а пользователь не может увидеть главный результат вехи: одну и ту же неделю
в четырёх вариантах ценовой политики.

## What Changes

- **Переключатель миров в «Городе»**: реестр миров на сервере (Эпоха + A/B/C/D из
  `list_worlds`), REST перечня, выбор мира переключает воспроизведение (позиция —
  на старт мира), лог мира строится фоновым детерминированным прогоном движка по
  правилу ветки реестра (мир в RAM побайтово равен БД ветки — детерминизм §3 плана).
- **Тумблер окраски «факт/прогноз»**: зоны красятся либо фактическим дефицитом
  закрытого бакета (как сейчас), либо `deficit_prob` тень-прогноза выбранной модели
  из `forecasts` БД текущего мира (для Эпохи — из `ml.db`); в прогреве (до окна
  активации) прогнозной окраски нет — факт.
- **Бейдж тарифа во всех мирах**: существующий surge-бейдж показывает тариф среды
  и множитель политики (у контурных веток ×1.15/×1.30/×1.50 из `price_mult` записей
  минут) — работает без переделки, закреплён сценарием на контурной ветке.
- **Seek-связка вкладок**: клик по точке графика «Лаборатории» прыгает карту на тот
  же момент; если текущий мир не «Эпоха» — переключить на «Эпоху» и прыгнуть
  (одно действие пользователя).

Не входит (§2 плана): вкладка «Сравнение» (change 5), экран параметров обучения
(выброшен решением вехи), live-режим как пользовательский, генерация миров из UI.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `web-replay-server`: ADDED — реестр миров и переключение (REST перечня миров,
  REST переключения с фоновым построением лога, честная метка мира Эпоха);
  ADDED — прогнозы текущего мира (REST читает `forecasts` БД выбранного мира).
- `web-city-ui`: ADDED — переключатель миров (выпадающий список, сброс позиции,
  состояние мира в `state`); ADDED — тумблер окраски «факт/прогноз»; MODIFIED —
  требование «Графики метрик с переходом по клику» (seek-связка с «Лабораторией»).

## Impact

- Код: `app/server.py` (реестр миров, REST `/api/worlds` + переключение + прогнозы
  мира, WS `state.world` с именем/меткой), `app/static/app.js`+`index.html`
  (выпадающий миров, тумблер, seek-связка), `app/static/map.js` (окраска прогнозом).
- Данные: `data/worlds/*.db` и `data/m3_epoch.db` — только чтение; новых данных нет.
- Тесты: `tests/test_web_server.py` (REST миров, переключение, прогнозы), лёгкий
  e2e канваса не входит (ручная приёмка, прецедент city-canvas).
- Зависимости: новых нет.
- Следующий change ест: `m6-compare-tab` (БД веток для исходов и выручки).
