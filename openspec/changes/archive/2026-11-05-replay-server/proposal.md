## Why

`live-engine` даёт движку поминутный событийный поток, но у него пока нет потребителя: браузеру нужен сервер, который превратит детерминированный прогон в управляемое воспроизведение — событийный лог с мгновенным seek в обе стороны, WebSocket-канал событий и REST для карты и метрик. Это серверное ядро «живого города» из тройки `live-engine` → `replay-server` → `city-canvas`: без него канвасу нечего рисовать и нечем управлять.

## What Changes

- Новый пакет `app/` — сервер воспроизведения: тихий фоновый прогон `Engine` с `on_minute` (шов `live-engine`) строит append-only событийный лог в памяти (записи `MinuteRecord` + строки `zone_metrics_5min` через in-memory writer); заполнение прогрессивное — первые минуты доступны почти сразу, 30 дней закрываются за десятки секунд; playhead не опережает край лога и ждёт пополнения.
- FastAPI-приложение (`python -m app`, Makefile-цель `make serve`):
  - `GET /api/city` — зоны с map-координатами, рёбра дорог и матрица кратчайших маршрутов как последовательностей зон (next-hop Флойд по конфигу дорог, без движка);
  - `GET /api/metrics` — захваченные строки `zone_metrics_5min` с фильтрами по зоне и диапазону времени (для графиков с кликом-переходом в `city-canvas`);
  - `GET /` — статика без сборки: служебная страница-заглушка (состояние воспроизведения и лента последних событий) — приёмка сервера без фронтенда; содержимое заменит `city-canvas`;
  - `WS /ws/replay` — протокол управления воспроизведением: команды `play`/`pause`/`speed`/`seek`, сообщения `state` (позиция, скорость, заполненный диапазон лога), `snapshot` (активные поездки и среда на минуту playhead — восстановление из лога), `records` (пачки пересечённых записей минуты), уведомление о росте заполненного диапазона.
- Зависимости: `fastapi` и `uvicorn[standard]` в `[project.dependencies]` (`pyproject.toml`), пакет `app` в `[tool.setuptools] packages`.
- Конфигурация: секция `app` в `common/config.py` и `config.yaml` (host, port, дни прогона лога) с дефолтами — старые конфиги грузятся (соглашение проекта).
- Актуализация `openspec/config.yaml`: устаревшие строки про Streamlit/plotly заменяются на FastAPI + WebSocket + canvas — обещание plan-m1 «текст актуализируем в вехе сервера».

Не меняется: движок и его механика (`live-engine` уже отдал шов), формат БД — серверу SQLite не нужен вовсе (самодостаточен: сам прогоняет seed из конфига), `simulator/`, `storage/`, `common/` (кроме новой секции конфига), M3-планы.

## Capabilities

### New Capabilities

- `web-replay-server`: сервер воспроизведения симуляции — событийный лог из тихого детерминированного прогона (прогрессивное заполнение, append-only, восстановление активных поездок на любую минуту), REST города (зоны/дороги/маршруты) и метрик, статика без сборки, WebSocket-протокол управления (play/pause/speed/seek, snapshot/records/state), запуск `python -m app` с конфиг-секцией и дефолтами.

### Modified Capabilities

(нет — новые требования не затрагивают существующие спецификации; `simulator-live` используется как есть, dependency change'а)

## Impact

- Файлы: новые `app/__init__.py`, `app/__main__.py`, `app/replay.py` (лог и фоновый прогон), `app/paths.py` (next-hop маршруты), `app/server.py` (FastAPI: REST/WS/статика), `app/static/index.html` (заглушка), `app/static/app.js`; правки `pyproject.toml` (зависимости + пакет), `common/config.py` (секция `AppCfg` с дефолтами), `config.yaml` (секция `app`), `Makefile` (цель `serve`), `openspec/config.yaml` (текст актуализации); тесты `tests/test_web_replay.py`, `tests/test_web_server.py` (по файлу на модуль — соглашение).
- Зависимости: `live-engine` (обязательная — шов `on_minute`; в конвейере применяется первым). Новые Python-пакеты: fastapi, uvicorn[standard] (виртуальное окружение `.venv`, установка через `make install`).
- Потребители: `city-canvas` — рисует карту по `/api/city`, анимируется `records`/`snapshot`, управляет через команды WS, строит графики по `/api/metrics`; будущее M6-ветвление — тот же протокол на логе ветки `price_fn`.
- Совместимость: сервер не требует сгенерированной БД; при seed конфига (42) лог байт-в-байт соответствует истории `taxi.db` (контракт детерминизма `simulator-loop`) — проверяется сверкой сумм событий и метрик в тестах.
- Ресурсы: лог 30 дней в памяти — порядка десятков МБ (записи минуты + строки метрик); фоновый прогон не блокирует обслуживание (отдельный поток, append-only списки immutable-записей).
