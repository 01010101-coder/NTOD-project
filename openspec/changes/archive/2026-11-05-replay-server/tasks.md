## 2. Событийный лог (app/replay.py)

- [x] 2.1 `ReplayLog`: append-only хранилище записей `MinuteRecord` и строк метрик, счётчик заполненности `filled`, чтение срезов `[start:filled]` по индексам минут; in-memory writer для `zone_metrics_5min`. Проверка: unit-тест — прогон движка 0.5–1 суток заполняет лог, записи читаются по мере прогона (до завершения), метрики в порядке `(ts, zone_id)`.
- [x] 2.2 Восстановление снимка по минуте t: активные поездки (назначения в записях ≤ t без высадки с тем же internal_id в записях ≤ t) со всеми маршрутными полями, среда записи t (`is_rain`, `price_mult`, `free_by_zone`). Проверка: unit-тест на коротком прогоне — снимок на минуте с известными активными поездками (построенными вручную из потока) совпадает; на пустой минуте (ночь старта) активных нет или ровно стартовые.
- [x] 2.3 Фоновый прогон при старте: отдельный поток, seed/days из CLI-флагов или конфига, записи и метрики пополняют лог прогрессивно. Проверка: unit-тест — запуск прогона в потоке на 0.5 суток: `filled` растёт и достигает `days × 1440` + дренаж; повторный прогон того же seed даёт идентичные записи (детерминизм лога).

## 5. WebSocket-протокол

- [x] 5.1 Подключение и состояние: при connect сервер шлёт `state` (позиция, скорость, playing, диапазон `filled`, seed/days/зоны) и `snapshot`; команды `play`/`pause` меняют продвижение. Проверка: TestClient-тест — connect получает `state`+`snapshot`; `pause` останавливает поток записей, `play` возобновляет в порядке минут.
- [x] 5.2 `seek` (ISO-минута): зажим в `[0, filled)`, после seek — `state` + `snapshot` новой минуты. Проверка: TestClient-тест — seek на известную минуту: snapshot содержит ожидаемые активные поездки; seek за край зажимается.
- [x] 5.3 `speed`: зажим [0.25, 600], фактическая скорость отражается в `state`. Проверка: TestClient-тест — скорость 0.01 и 10000 зажимаются к границам, `state` несёт зажатое значение.
- [x] 5.4 Продвижение и пачки: серверный тик пересекает записи со скоростью сим-мин/сек, отправляет пачками с лимитом записей; на краю незаполненного лога — ожидание пополнения, продолжение с новой записи. Проверка: TestClient-тест на коротком прогоне в фоне — при достижении края поток приостанавливается, после дозаполнения продолжается.
