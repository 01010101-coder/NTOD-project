# Design: m6-rng-branches

## Context

Сейчас `Engine.__init__` создаёт один `np.random.default_rng(seed)` и передаёт его
и `WorldEnv` (экзогенные суточные розыгрыши: дождь, surge-инъекции —
`simulator/env.py:advance_day`), и `spawn_requests` (эндогенные: пуассоновский
спавн `demand.py:127` и выбор назначения `demand.py:162`). Потребителей rng ровно
два (больше в `simulator/` нет: парк стартует без rng §10.14, диспатч
детерминирован). Мотивация разделения — proposal.md (Why): политика ветки меняет
λ → эндогенные розыгрыши меняют расход потока → при общем потоке разъезжается
погода. План вехи — `docs/plan-m5-m6-policy.md` §3.

## Goals / Non-Goals

**Goals:** раздельные потоки с сохранением детерминизма; скелет веточного
генератора (ветка `a-base`, CLI, конвенция `data/worlds/`); общая sqlite-подложка
прогонов для двух CLI без копирования формата §4 M2.

**Non-Goals (design-уровень):** политики и `policy:`-секция конфига (`m6-policy`);
ветки B/C/D, δ-калибровка, тень-прогнозы, Makefile-цели полного свипа миров
(`m6-worlds`); реестр миров в приложении/сервере; перегенерация эталонных БД
`taxi.db`/`m3_epoch.db` и любые правки `storage/`; подъём `worlds_dir` в конфиг —
до потребности остаётся константой модуля.

## Decisions

1. **Расщепление через `SeedSequence.spawn(2)`, порядок закреплён.**
   `ss = np.random.SeedSequence(seed)`; `endo_ss, exo_ss = ss.spawn(2)`;
   `self._rng = np.random.default_rng(endo_ss)` (эндогенный — его получают
   `spawn_requests`), `self._rng_env = np.random.default_rng(exo_ss)` (передаётся
   `WorldEnv`). Порядок детей `[эндогенный, экзогенный]` закреплён тестом и
   спека-сценарием «Seed по умолчанию берётся из конфига». `seed=None` →
   `SeedSequence(None)` даёт энтропийный мир — семантика «случайный мир»
   сохраняется. Альтернатива «два независимых `default_rng(seed)` / `default_rng(seed+1)`»
   отвергнута: коррелированные/производные seed-ы — коллизионно и непрозрачно;
   `spawn` — канонический механизм numpy для независимых дочерних потоков.

2. **Контракт `WorldEnv(cfg, rng)` не меняется.** Среда по-прежнему получает один
   генератор — меняется то, какой именно генератор передаёт `Engine`. Спека
   `simulator-env` не трогается; правка локализована в `engine.py` (+docstring:
   ссылку «один rng на мир (§10.9)» заменить на разделение потоков, §3 плана
   M5+M6).

3. **Вынос прогона-подложки в `simulator/writers.py`.** `SqliteTripWriter`,
   `print_progress`, `print_summary` переносятся из `simulator/__main__.py` без
   изменения поведения (публичные имена, без подчёркивания); `__main__`
   переиспользует их импортом. Причина: CLI `simulator.branches` обязан печатать
   тот же формат §4 и использовать тот же writer — копирование 60 строк в соседний
   модуль хуже переноса. Существующие тесты CLI `simulator` (формат вывода,
   guard) остаются в силе без правок. Альтернатива «импорт приватных имён из
   `__main__`» отвергнута: приватный кросс-модульный импорт — запах, который
   verify пометит.

4. **Реестр веток — словарь имён в `simulator/branches.py`.**
   `WORLDS_DIR = Path("data/worlds")` — константа модуля (прецедент:
   `_REPORTS_DIR = Path("reports")` в `calibrate.py`, аргумент `--out` планом не
   назван; подъём в конфиг — когда появится потребитель в `m6-policy`/`m6-worlds`).
   Запись реестра — `dataclass BranchSpec(name, price_fn_factory=None)`;
   `BRANCHES: dict[str, BranchSpec] = {"a-base": BranchSpec("a-base")}`.
   Подключение ветки B/C/D в `m6-worlds` = новая запись с фабрикой `price_fn` +
   (позже) окно активации — генератор не переписывается.
   `generate_branch(name, cfg, *, seed=None, days=37, db_path=None)` строит
   `Engine(cfg, seed=seed, price_fn=spec.price_fn_factory(cfg) if factory else None)`
   и гонит прогон через `SqliteTripWriter`; БД по умолчанию
   `WORLDS_DIR / f"{name}.db"`; каталог создаётся (`os.makedirs`, как в `__main__`);
   guard непустой `trips` — то же сообщение и exit-код (константа импортируется,
   не дублируется).

5. **CLI `python -m simulator.branches`** — модуль `simulator/branches.py` с
   `main(argv) -> int` (прецедент: `__main__.py`, `calibrate.py`; отдельный модуль
   вместо подкоманды `simulator` — устоявшийся в проекте паттерн «один CLI — один
   модуль»). Аргументы: `--branch` (обязателен), `--days` (дефолт 37 — формат
   ветки «30 истории + тест-неделя», §3 плана), `--config`, `--seed`, `--db`.
   Дефолт 37 — единственное новое «магическое число», обосновано планом и
   продублировано в дефолте `generate_branch`.

6. **Тест независимости потоков — красный до, зелёный после.** Два движка, один
   seed: базовый и с `price_fn = lambda z, t: 3.0` (α = 1 → λ/3 → меньше заказов →
   эндогенный поток расходится иначе). После N дней (например 3) поминутные опросы
   `is_rain`/`price_multiplier` обеих сред совпадают, а таблицы `trips`
   различаются. До разделения этот тест падает (расход эндо-потока сдвигал общий
   генератор среды) — он и есть регрессионная суть change'а. Доступ к среде для
   теста — публичные запросы `env.is_rain`/`env.price_multiplier` по всем минутам
   (приватные списки эпизодов не читаем).

7. **Побитовая повторяемость ветки** — короткий прогон (2 дня) `generate_branch`
   дважды в tmp-каталоги, сравнение экспортов таблиц (прецедент `epoch_check` M3:
   `storage.csv_export.export_table` + сравнение содержимого). Отдельный
   full-size-прогон на 37 дней не тестом, а приёмкой (25–50 с).

## Risks / Trade-offs

- [Побитовая связь с эталонами M2/M3 разрывается] → Осознанно: план M5+M6 §3
  принимает (эпоха — самостоятельная запись, ветки сравниваются между собой).
  Эталонные БД не перегенерируются; контроль коридора — приёмка.
- [После перестройки `deficit_share` выйдет из коридора [10, 20] %] → Приёмка:
  `python -m simulator.calibrate --days 30` и сводка `a-base`; коридор имеет запас
  (18.8 % на старой разводке); при выходе — стоп и перес-калибровка до веток
  (ворота change'а, план §8.1), не тишина.
- [`spawn` детерминирован между версиями numpy?] → Внутри зафиксированной среды
  `.venv` — да; межверсионная стабильность не контрактуется и раньше
  (`default_rng(seed)`), тесты ловят на месте.
- [Тест независимости требует, чтобы α-эластичность реально давала расхождение
  заказов] → ×3 при α = 1 делит λ на 3 — расхождение таблиц гарантировано;
  тест дополнительно утверждает неравенство `trips` (не только равенство среды),
  иначе проверка бессильна.

## Migration Plan

Изменение атомарно внутри репозитория: правки `engine.py` + вынос `writers.py` +
новые `branches.py`/тесты. Отката не требуется (новое поведение покрыто тестами;
старые CLI неизменны). Эталонные БД и артефакты M3 не мигрируются.

## Open Questions

Нет — размерности решений закрыты планом вехи и решениями выше.
