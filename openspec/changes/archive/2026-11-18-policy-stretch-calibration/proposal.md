## Why

Ступенчатая политика C/D задумана с тремя ступенями тарифа: ×1.15 / ×1.30 / ×1.50 при `p_eff ≥ 0.4 / 0.6 / 0.8`. Разбор тест-недели показал, что в мирах C и D за всю неделю срабатывала только ×1.15 (C — 900 раз, D — 696), а ×1.30 и ×1.50 — ни разу.

Причина в формуле калибровки: `p_eff = clip(p + δ, 0, 1)`. Чтобы сети вмешивались в ~10 % зона-моментов, δ получился ≈ −0.44. Тогда даже `p = 1.0` даёт `p_eff = 0.56`, и пороги 0.6 и 0.8 недостижимы. «Ступенчатая» политика фактически одноступенчатая, а вывод сравнения миров сделан не о той политике, что описана в плане.

## What Changes

- **Растяжение вместо сдвига вниз.** Для `δ < 0` эффективная вероятность — `p_eff = clip((p + δ) / (1 + δ), 0, 1)`: отрезок `[−δ, 1]` растягивается на `[0, 1]`. Порог первой ступени и частота вмешательств сохраняются, `p = 1 → 1`, поэтому уверенный прогноз доходит до верхних ступеней. Для `δ ≥ 0` формула прежняя (`clip(p + δ)`), существующие сценарии не меняются.
- Новая функция `simulator.policy.effective_prob` (скаляр и массив numpy) — единственная реализация; её используют `stair_multiplier` и калибровка `fire_fraction`.
- Повторная δ-калибровка: `shift: {mlp: −0.719, lstm: −0.688}` (частоты 0.098 / 0.100), синхронно в `config.yaml` и дефолтах `common/config.py`.
- Пересборка миров C и D. Результат тест-недели: C — ×1.15/×1.30/×1.50 = 346/291/215 зона-бакетов, доля дефицита 15.4 % (−15 % к A); D — ×1.15/×1.30 = 514/73, 18.0 % (−1.6 % к A). LSTM реже достигает p ≥ 0.95, поэтому ×1.50 у D не встречается.
