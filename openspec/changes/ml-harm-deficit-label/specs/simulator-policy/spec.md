## MODIFIED Requirements

### Requirement: Реактивное правило ветки B

Реактивная политика (ветка `b-reactive`, анти-пример ТЗ) SHALL давать множитель `policy.reactive_mult`, если в последнем закрытом бакете зоны есть дефицит по правилу контракта (`free_drivers / max(requests, 1) < 0.5` или `unfulfilled > 0`), иначе 1.00. Правило реактивной политики SHALL NOT зависеть от `ml.deficit_label`: при `harm` реактивная ветка срабатывает так же, как при `legacy`. Реактивная политика SHALL NOT использовать прогноз и упреждение — только факт последнего закрытого бакета; сглаживание и гистерезис не применяются (мигание у границы — часть патологии, которую ветка контрастирует). Итоговый тариф — по требованию композиции (умножение на тариф мира, потолок `total_cap`).

#### Scenario: Дефицит сейчас → реактивный множитель

- **WHEN** последняя закрытая строка метрик зоны имеет `unfulfilled > 0` (или `free_drivers / max(requests, 1) < 0.5`)
- **THEN** множитель реактивной политики равен `reactive_mult` (×1.30 по прил. А), итоговый тариф = min(тариф_мира × 1.30, total_cap)

#### Scenario: Правило не зависит от метки моделей

- **WHEN** конфиг содержит `ml.deficit_label: harm`, а последняя закрытая строка зоны имеет `free_drivers = 1`, `requests = 10`, `unfulfilled = 0`
- **THEN** множитель реактивной политики равен `reactive_mult`

#### Scenario: Спокойная зона → множитель 1.00

- **WHEN** последняя закрытая строка метрик зоны без дефицита по правилу контракта
- **THEN** множитель равен 1.00, итоговый тариф равен тарифу мира

#### Scenario: Нет закрытых бакетов — прогрев

- **WHEN** у зоны ещё нет ни одного закрытого бакета (самое начало мира)
- **THEN** множитель равен 1.00 — правило не срабатывает до появления факта
