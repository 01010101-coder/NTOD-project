## Context

Мотивация — в proposal.md, раздел Why. К моменту реализации в коде есть все механизмы (пять предыдущих change'ей), выключенные по умолчанию. Ограничения:

- Тесты читают `config.yaml` как эталон, равный дефолтам. Эталонный тест хэшей фиксирует мир по дефолтам.
- `ARTIFACTS_ROOT = Path("artifacts")` — константа в `ml/train.py`. Её импортируют `ml/infer.py`, `ml/__main__.py`, `simulator/policy.py`, `simulator/branches.py`, `simulator/policy_calibration.py`, `app/server.py`. «Свежайший каталог семейства» выбирается по имени и дате.
- Все CLI уже принимают `--config`.
- `app/compare.py` считает исходы по `trips`/`zone_metrics_5min` веток и не знает про отказы.
- Ноутбук подбора стартовых условий не собран. Его материал — `notebooks/stop.md` и модули `notebooks/*_lab.py`.

## Goals / Non-Goals

**Goals:**
- Один воспроизводимый конвейер «конфиг → данные → модели → калибровки → сетка → приложение» для финального мира.
- Изоляция от старого мира: старые БД, артефакты, ноутбуки и тесты не меняются.
- Вкладка сравнения показывает метрики, по которым политики реально различаются (`notebooks/stop.md` §7–§21).

**Non-Goals:**
- Новые механизмы.
- Перевод тестов на финальный конфиг.
- Удаление старого мира.

## Decisions

### 1. Отдельный `config.final.yaml`, эталонный `config.yaml` не трогаем

Тесты и эталонные хэши держатся на `config.yaml` и дефолтах, старые ноутбуки и БД — тоже. Отдельный файл и `--config`/`CONFIG` во всех точках входа дают финальный мир без каскада правок тестов.

Альтернатива — переписать `config.yaml` и дефолты моделей. Это сломало бы десятки тестов и эталонные хэши, а старые результаты M2–M6 потеряли бы воспроизводимость. Отклонена.

### 2. `ml.artifacts_root` вместо константы

Иначе обучение финального мира сделало бы свои сети «свежайшими» для старого, и старые ветки и ноутбуки молча подхватили бы чужие сети. Константа остаётся дефолтом поля. Функции, которые сейчас берут её по умолчанию, получают корень из `cfg.ml.artifacts_root`.

### 3. Значения финального мира — из ноутбука, по критериям приёмки

Стартовая точка — мир e11 (`notebooks/stop.md` §12): n=240, смены по умолчанию, радиус 12, `cancel_grace_min` 5, `cancel_prob_per_min` 0.06, `cancel_max_prob` 0.9, отклик водителей по умолчанию, α = 0.5. Плюс вызов (`part` 60, `lag_min` 60, `session_min` 120) и шоки по умолчанию.

Подбор меняет только σ шоков, `part`/`lag_min` вызова и при необходимости `drivers.count`. Подбор идёт по трём seed (42/7/2026), критерии:

1. база (ветка A), тест-неделя: необслуженных 3–6 %, p95 загрузки 85–97 %;
2. сети планирования на эпохе финального мира: AP MLP на H = 60 не ниже AP календаря + 0.03 (§19: без шоков выигрыш ~0);
3. реактивная политика в канале `both` спасает заказы (`saved > 0`), у вызова ненулевые часы — рычаг работает.

Если критерий 2 недостижим при σ города ≤ 0.25, это фиксируется в ноутбуке как результат. Тогда выбирается σ с наибольшим выигрышем при выполненном критерии 1. Мир не подгоняется дальше, чем требует реализм.

### 4. Канал `both`

Реальные платформы одновременно ставят цену пассажиру и сигналят водителям. `heatmap` и `price` остаются абляциями в ноутбуке (`make_cfg({"policy.channel": …})`).

### 5. Новые исходы вкладки считаются из БД веток и `meta.json`

- `cancelled`/`unserved` — по статусу `cancelled` в `trips`.
- `deterred`/`saved` — разность с A в одном ответе.
- `price_switches` — по `price_multiplier` соседних бакетов зоны в `zone_metrics_5min`. Сюда входят и инъекции тарифа мира: база A задаёт «фон» переключений.
- `callout_hours` — из `meta.json`, потому что в таблицах нет `driver_id`.

### 6. `make world` — последовательность существующих CLI

Новой логики нет, только порядок и `--config $(CONFIG)` на каждом шаге. Остановка на первой ошибке — штатное поведение make.

## Risks / Trade-offs

- [Критерии приёмки мира несовместимы (шоки, нужные сети, ломают уровень необслуженных)] → Порядок важности: 1 > 3 > 2. Компромисс фиксируется в ноутбуке.
- [Время конвейера: эпоха 37 дней, 4 сети, 4 ветки с тенью] → ~15–25 мин на ноутбуке с 8 ГБ. Генерацию веток запускать последовательно, не параллельно (опыт e16: swap).
- [Старые сетки без `meta.json`] → Вкладка отдаёт `null` (сценарий спеки).

## Migration Plan

Миграции существующих данных нет. Новые данные создаются в `data/final/` и `artifacts/final/`. Откат — удалить эти каталоги и `config.final.yaml`.
