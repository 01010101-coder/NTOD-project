# data-storage Specification

## Purpose
Слой хранения проекта: SQLite-схема всех трёх таблиц контракта данных (trips, zone_metrics_5min, forecasts), доступ к данным (батч-вставка, выборки по таблице/зоне/времени), CSV-экспорт и демо-скрипт — несущая конструкция, на которую опираются симулятор M2, ML M3 и сервер воспроизведения M4.

## Requirements

### Requirement: Схема таблиц контракта данных

Слой хранения SHALL создавать в БД три таблицы контракта данных — `trips`,
`zone_metrics_5min`, `forecasts` — с колонками, типами, ограничениями
NOT NULL/CHECK и первичными ключами: `status IN ('completed','cancelled',
'unfulfilled')` для trips, составной PRIMARY KEY `(ts, zone_id)` у
zone_metrics_5min и `(ts, zone_id, horizon_min, model_version)` у forecasts —
ключ forecasts дополнен `model_version`, чтобы несколько версий моделей
(наивы и сети вехи M3) лежали в таблице рядом на одних парах (ts, зона,
горизонт). Индексы: `trips(created_at)`, `trips(origin_zone)`,
`forecasts(model_version)`.

Инициализация схемы SHALL обеспечивать этот ключ и на уже существующих БД:
таблица `forecasts` старой формы (PK без `model_version`) пересоздаётся
(DROP + CREATE в одной транзакции), если она пуста; непустая таблица старой
формы — отказ с понятной ошибкой, без потери данных; таблица новой формы —
no-op. Инициализация остаётся идемпотентной.

#### Scenario: Инициализация пустой БД создаёт схему

- **WHEN** инициализация выполняется на пустом файле БД
- **THEN** существуют все три таблицы с колонками контракта и все три индекса,
  PK forecasts — (ts, zone_id, horizon_min, model_version)

#### Scenario: Недопустимый статус trips отклоняется

- **WHEN** в trips вставляется строка со статусом, не входящим в
  `('completed','cancelled','unfulfilled')`
- **THEN** вставка падает с ошибкой нарушения ограничения, и строка не
  записывается

#### Scenario: Миграция пустой таблицы старой формы

- **WHEN** инициализация выполняется на БД, где `forecasts` создана старым DDL
  (PK без `model_version`) и пуста
- **THEN** таблица пересоздана с PK (ts, zone_id, horizon_min, model_version),
  прочие таблицы и их строки не затронуты

#### Scenario: Отказ на непустой таблице старой формы

- **WHEN** инициализация выполняется на БД со старой формой `forecasts`, в
  которой есть строки
- **THEN** инициализация завершается ошибкой с сообщением о необходимости
  очистить таблицу, данные не изменены

#### Scenario: Повторная инициализация новой формы — no-op

- **WHEN** инициализация выполняется второй раз на БД, где `forecasts` уже
  новой формы и содержит строки
- **THEN** команда завершается без ошибок, строки сохранены

#### Scenario: Несколько версий на одном ключе

- **WHEN** в forecasts вставлены две строки с одинаковыми (ts, zone_id,
  horizon_min) и разными model_version
- **THEN** обе строки успешно записаны и читаются

### Requirement: Идемпотентная инициализация
Инициализация схемы SHALL быть идемпотентной: повторный запуск на существующей БД завершается без ошибок, не пересоздаёт таблицы и сохраняет все ранее записанные строки.

#### Scenario: Повторный init без ошибок
- **WHEN** инициализация выполняется второй раз на БД, в которую уже записаны строки
- **THEN** команда завершается без ошибок, и все ранее записанные строки остаются доступны для чтения

### Requirement: Прагмы соединения
Каждое открываемое соединение с БД SHALL включать прагмы `foreign_keys=ON` и `journal_mode=WAL` (план M1 §6; WAL — чтобы M4 мог читать во время записи).

#### Scenario: Прагмы применены
- **WHEN** соединение открыто и запрошены текущие значения прагм `foreign_keys` и `journal_mode`
- **THEN** возвращаются `1` и `wal` соответственно

### Requirement: Транзакции
Слой хранения SHALL предоставлять транзакционный блок: при нормальном завершении изменения фиксируются, при исключении — откатываются целиком.

#### Scenario: Коммит при успехе
- **WHEN** внутри транзакционного блока записаны строки и блок завершён без исключения
- **THEN** строки читаются из БД новым соединением

#### Scenario: Rollback при исключении
- **WHEN** внутри транзакционного блока записаны строки, а затем возбуждено исключение
- **THEN** исключение пробрасывается наружу, и записанные в блоке строки в БД отсутствуют

### Requirement: Пакетная вставка
Слой хранения SHALL вставлять несколько строк таблицы одной операцией в одной транзакции; для trips сгенерированные `trip_id` SHALL быть доступны вызывающему коду после вставки.

#### Scenario: Батч из N строк одной операцией
- **WHEN** в таблицу передан список из N строк одной операцией вставки
- **THEN** в таблице ровно N строк, и для trips возвращены N сгенерированных уникальных `trip_id`

### Requirement: Выборки по таблице, зоне и времени
Слой хранения SHALL предоставлять выборки для каждой из трёх таблиц с опциональными фильтрами по зоне и диапазону времени; без фильтров возвращаются все строки таблицы.

#### Scenario: Выборка без фильтров
- **WHEN** запрошены все строки таблицы без фильтров
- **THEN** возвращены все записанные в неё строки со значениями полей, равными записанным

#### Scenario: Фильтр по зоне
- **WHEN** запрошены строки с фильтром по zone_id
- **THEN** возвращены только строки этой зоны

#### Scenario: Фильтр по диапазону времени
- **WHEN** запрошены строки с фильтром по диапазону времени (от-до)
- **THEN** возвращены только строки, чьё временнóе поле лежит в диапазоне, включая границы

### Requirement: Время хранится ISO-текстом
Все временны́е значения (`created_at`, `assigned_at`, `pickup_at`, `dropoff_at`, `ts`) SHALL храниться в БД текстом формата «YYYY-MM-DD HH:MM:SS» (наивное время, секунды 00) — по контракту данных и решению §7.2 плана M1.

#### Scenario: Формат хранения проверен напрямую в БД
- **WHEN** строки записаны через слой хранения и прочитаны прямым SQL-запросом, минуя слой хранения
- **THEN** каждое временнóе поле — строка формата «YYYY-MM-DD HH:MM:SS» с секундами «00»

### Requirement: CSV-экспорт таблиц
Слой хранения SHALL выгружать любую из трёх таблиц в CSV: первая строка файла — имена колонок, далее — те же строки, что хранятся в таблице; NULL-значения выгружаются пустыми полями.

#### Scenario: CSV содержит те же строки
- **WHEN** таблица с записанными строками выгружена в CSV
- **THEN** заголовок CSV равен списку колонок таблицы, а строки данных совпадают со строками, возвращаемыми выборкой из этой таблицы

### Requirement: Демо-скрипт
Пакет `storage` SHALL предоставлять запускаемый демо-скрипт `python -m storage.demo`, который создаёт временную БД, записывает по строке в каждую из трёх таблиц, читает их обратно и выгружает CSV, не трогая БД из `config.yaml`.

#### Scenario: Демо-скрипт завершается успехом
- **WHEN** команда `python -m storage.demo` выполнена в окружении проекта
- **THEN** процесс завершается с кодом 0, печатает сводку записанных/прочитанных строк и путь к выгруженному CSV, а `data/taxi.db` из эталонного конфига не создаётся и не изменяется
