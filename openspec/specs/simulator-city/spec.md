# simulator-city Specification

## Purpose
Модель города симулятора M2: зоны-архетипы с весами источника/цели (§3.1 плана `docs/plan-m2-engine.md`), двунаправленный дорожный граф с весами-минутами и матрица кратчайших путей `path_min` (Флойд, §3.2), суточные профили спроса по архетипам. `build_city(cfg)` собирает неизменяемый `CitySpec`, которым пользуются все модули движка (спрос, водители, среда, цикл).

## Requirements

### Requirement: Публичные типы модели города

Модуль города SHALL предоставлять публичные типы по приложению Б плана `docs/plan-m2-engine.md`: зона `ZoneInfo` с полями `id`, `name`, `archetype`, `attract_origin`, `attract_dest`; профиль `HourProfile` с массивами `weekday` и `weekend` длины 24 каждая; спецификация города `CitySpec` с зонами (сортированы по `id`, `id = 0..Z-1` без пропусков), матрицей `path_min` размера `(Z, Z)` из целых чисел и профилями `profiles` — по архетипам из зон. Координаты карты `map:{x, y}` SHALL не попадать в `ZoneInfo` (§3.1: движок их не читает, они нужны только карте M5).

#### Scenario: Построение города из эталонного конфига

- **WHEN** город строится из эталонного `config.yaml` (приложение А плана M2)
- **THEN** спецификация содержит 6 зон, отсортированных по `id` от 0 до 5 без пропусков; у каждой зоны заполнены `id`, `name`, `archetype`, `attract_origin`, `attract_dest` и нет поля координат карты; `profiles` содержит ровно архетипы зон эталона (`residential`, `business`, `airport`, `mixed`); `path_min` — целочисленная матрица 6×6

#### Scenario: Координаты карты изолированы

- **WHEN** зона в конфиге задана с `map: {x: 180, y: 180}` (эталон, приложение А)
- **THEN** построенный объект зоны не содержит `x`/`y` и вложенного `map` — координаты не попадают в модель города

### Requirement: Матрица кратчайших путей path_min

При построении города SHALL вычисляться матрица кратчайших путей `path_min` по дорожному графу (алгоритм Флойда; §3.2 плана M2 — матрица считается при старте, не хранится в конфиге). Для эталонного графа матрица SHALL быть симметричной (рёбра двунаправленные), с нулями на диагонали и положительной вне диагонали, и SHALL содержать кратчайшие расстояния в минутах: путь через транзитные зоны не короче значения в матрице, вес прямого ребра не меньше значения в матрице.

#### Scenario: Свойства эталонной матрицы

- **WHEN** город построен из эталонного конфига (7 дорог, приложение А)
- **THEN** `path_min` симметрична (`path_min[A][B] = path_min[B][A]`), на диагонали нули, вне диагонали положительные значения

#### Scenario: Кратчайший путь через транзит

- **WHEN** вычисляется время между зонами, не соединёнными прямым ребром (например, 0 → 3: прямого ребра нет, пути 0→2→3 = 15 и 0→5→2→3 = 19)
- **THEN** `path_min[0][3]` равен 15 — минимум по всем маршрутам; для зон с прямым ребром (например, 1 → 4 = 14) значение равно весу ребра

### Requirement: Валидность города при построении

Построение города SHALL проверять корректность конфига города и SHALL завершаться понятной ошибкой без возврата спецификации, если: идентификаторы зон не уникальны или образуют ряд с пропусками (нарушен контракт `id = 0..Z-1` приложения Б); дорожный граф не связный (между некоторыми зонами нет пути — матрица кратчайших путей не определена).

#### Scenario: Уникальность zone_id

- **WHEN** в конфиге города две зоны имеют одинаковый `id`
- **THEN** построение завершается понятной ошибкой; спецификация города не возвращается

#### Scenario: Непрерывность id

- **WHEN** в конфиге города идентификаторы образуют ряд с пропуском (например, 0, 1, 3)
- **THEN** построение завершается понятной ошибкой; спецификация города не возвращается

#### Scenario: Связность графа

- **WHEN** в конфиге города есть зона, не достижимая из остальных по дорогам (граф распадается на компоненты)
- **THEN** построение завершается понятной ошибкой о несвязном графе; спецификация города не возвращается

### Requirement: Профили спроса по архетипам

Профили спроса SHALL строиться по архетипам зон из конфига: каждый архетип даёт профиль с массивами `weekday` и `weekend` длины 24 (множители на часы 00–23). Для эталонного конфига (приложение А) профили SHALL существовать для всех 4 архетипов (`residential`, `business`, `airport`, `mixed`) и для будней, и для выходных, и все значения SHALL быть неотрицательными.

#### Scenario: Профили эталона полны

- **WHEN** город построен из эталонного конфига
- **THEN** профили существуют для всех 4 архетипов; каждый содержит `weekday` и `weekend` длины 24; все 24×2 значений каждого архетипа неотрицательны

#### Scenario: Профили дефолтного конфига полны

- **WHEN** город построен из конфигурации целиком из дефолтов (пустой конфиг)
- **THEN** результат по профилям совпадает с эталонным: 4 архетипа, `weekday` и `weekend` длины 24, значения неотрицательны (дефолты равны каноническим значениям приложения А)
