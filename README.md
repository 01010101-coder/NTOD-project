# Прогноз дефицита такси и ценовые политики

Сквозной проект по курсу «Нейросетевые технологии обработки данных».

Проект моделирует такси в небольшом синтетическом городе. Нейросети (MLP и LSTM)
по истории города предсказывают спрос и дефицит машин по зонам на 15–30 минут
вперёд. Поверх прогноза работают ценовые политики, которые заранее поднимают
тариф там, где ожидается дефицит. Всё можно посмотреть в веб-интерфейсе: живая
карта города, лаборатория метрик моделей и сравнение «миров» с разными
политиками на одной и той же неделе.

## Из чего состоит

| Каталог | Что внутри |
|---|---|
| `simulator/` | Дискретно-событийный симулятор города: 6 зон, дороги, спрос по часам и архетипам зон, дождь, «пятничный вечер», водители, диспетчеризация, агрегация 5-минутных метрик. Плюс ценовые политики, ветки «миров» и калибровки. |
| `ml/` | Датасет со скользящим окном и защитой от утечек, модели MLP и LSTM (PyTorch) с общим туловищем, наивные бейзлайны, обучение, walk-forward инференс, метрики. |
| `storage/` | Схема SQLite, репозиторий, экспорт в CSV. |
| `common/` | Загрузка и валидация конфига (pydantic), логирование, работа со временем. |
| `app/` | Сервер на FastAPI с REST и WebSocket и фронтенд на чистом JS (`app/static/`): вкладки «Город», «Лаборатория» и «Сравнение». |
| `config.yaml` | Единый конфиг: город, спрос, водители, погода, тарифы, гиперпараметры ML, политики. |
| `scripts/` | Приёмка вехи M2 и контроль целостности эпохи данных. |
| `notebooks/` | Исследовательский ноутбук по применимости MLP. |
| `tests/` | Тесты pytest для всех модулей. |
| `docs/` | Спецификация проекта (PDF), планы вех M1–M6, отчёт о калибровке. |
| `openspec/` | Спецификации возможностей и архив изменений (процесс разработки по OpenSpec). |

### Как это работает

1. **Мир.** Симулятор шаг за шагом в сим-минутах генерирует заказы и поездки.
   Результат записывается в SQLite: таблица `trips` и 5-минутные агрегаты по зонам
   `zone_metrics_5min` (заказы, свободные водители, невыполненные заказы, ожидание и т. д.).
   При одинаковом seed прогон детерминирован.
2. **Дефицит.** 5-минутка зоны считается дефицитной, если
   `free_drivers / max(requests, 1) < 0.5` или `unfulfilled > 0`.
   Мир откалиброван так, что дефицитных интервалов 10–20 %.
3. **ML.** Эпоха данных длиной 37 дней: 30 дней обучения (из них 2 на валидацию)
   и 7 дней тестового продолжения. MLP и LSTM прогнозируют спрос (регрессия)
   и вероятность дефицита (классификация) на горизонтах 15 и 30 минут.
   Их сравнивают с двумя наивными прогнозами по MAE/RMSE, precision/recall/F1 и калибровке.
4. **Политики.** На тестовой неделе один и тот же мир (тот же seed) прогоняется
   в четырёх ветках:
   - `a-base` — без политики;
   - `b-reactive` — реактивная политика: тариф ×1.3, когда дефицит уже наступил;
   - `c-mlp` и `d-lstm` — ступенчатый тариф (×1.15 / ×1.3 / ×1.5) по прогнозу
     вероятности дефицита от MLP и LSTM соответственно. Сдвиг порогов откалиброван так,
     чтобы обе сети вмешивались одинаково часто.

   Вкладка «Сравнение» показывает поездки, невыполненные заказы, ожидание
   и выручку по веткам.

## Требования

- Python 3.11+
- `make` (macOS и Linux; на Windows подойдёт WSL)
- около 2 ГБ места под виртуальное окружение (PyTorch)

## Установка

```bash
git clone https://github.com/01010101-coder/NTOD-project.git
cd NTOD-project
make install        # создаёт .venv и ставит проект с dev-зависимостями
```

Если в системе нет `python3.11`, создайте окружение вручную любым Python ≥ 3.11:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

## Быстрый старт: только карта города

```bash
make serve          # то же, что .venv/bin/python -m app
```

Откройте <http://127.0.0.1:8000>. Сервер сам прогоняет 30 дней мира в фоне,
и на вкладке «Город» воспроизводится карта с машинами и дефицитом по зонам.
Вкладкам «Лаборатория» и «Сравнение» нужны данные полного конвейера (см. ниже).

Флаги сервера: `--seed`, `--days`, `--host`, `--port`, `--config`.

## Полный конвейер

Данные (`data/`) и обученные модели (`artifacts/`) в репозиторий не входят:
они воспроизводятся командами ниже (seed 42, детерминированно).

```bash
# 1. Эталонная история: 30 дней, data/taxi.db
make sim

# 2. Эпоха ML: 37 дней, data/m3_epoch.db; первые 30 дней совпадают с taxi.db
make epoch
make epoch-check                        # проверка этого совпадения по md5

# 3. Обучение MLP и LSTM, артефакты в artifacts/<model>-v1-<дата>/
.venv/bin/python -m ml train --arch both
# (необязательно) подбор окна истории 3/6/12 часов
.venv/bin/python -m ml sweep

# 4. Walk-forward прогноз на тестовой неделе: таблица forecasts и сводка метрик
.venv/bin/python -m ml infer

# 5. Калибровка сдвигов порогов политик (обновляет policy.shift в config.yaml)
.venv/bin/python -m simulator.policy_calibration

# 6. Четыре мира с политиками в data/worlds/{a-base,b-reactive,c-mlp,d-lstm}.db
.venv/bin/python -m simulator.branches --all

# 7. Веб-интерфейс со всеми вкладками
make serve
```

Повторный запуск генерации в непустую БД завершится с кодом 2: так защищены
уже сгенерированные данные. Чтобы сгенерировать заново, удалите
соответствующий файл в `data/`.

### Дополнительно

```bash
.venv/bin/python -m simulator --days 1 --seed 7 --db data/test.db --csv data/test_csv
                                          # произвольный прогон с выгрузкой в CSV
.venv/bin/python -m simulator.calibrate --days 30
                                          # графики калибровки мира в reports/
make accept-m2                            # автоматическая приёмка вехи M2
```

## Разработка

```bash
make test           # pytest
make lint           # ruff check и ruff format --check
make fmt            # автоформатирование
```

## Конфигурация

Все параметры мира, моделей и политик задаются в `config.yaml`. Конфиг
валидируется строго: неизвестные ключи считаются ошибкой. Другой конфиг можно
передать любой команде флагом `--config path.yaml`.
