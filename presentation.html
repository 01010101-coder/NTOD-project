Прогноз дефицита такси и ценовые политики

Синтетический город, нейросети MLP и LSTM, которые видят нехватку машин за 15–30 минут, и тариф, который реагирует заранее.

Проблема

Когда дефицит виден, бороться с ним уже поздно

⏱

Реакция по факту

Тариф поднимается, когда машин уже нет. Пока водители доедут из соседней зоны (5–10 мин), пик проходит.

🔮

Прогноз

Нейросеть по истории города оценивает спрос и вероятность дефицита в каждой зоне на 15 и 30 минут вперёд.

⚖

Честная проверка

Один и тот же мир (тот же seed) прогоняется с разными политиками. Сравнение идёт на одной и той же неделе.

Главный вопрос: лучше ли прогнозный тариф, чем реактивный и чем отсутствие политики?

Как работает симулятор

Каждая сим-минута проходит пять шагов

Среда

Марковские переходы погоды, календарь, «пятничный вечер», тариф

Спрос

Пуассон с мультипликативной λ: час × архетип × погода × событие, эластичность по тарифу

Диспатч

Ближайший свободный водитель, ничья по id. Заказ ждёт не дольше 6 мин

Движение

Подача и поездка по матрице путей, в дождь дольше

Агрегация

5-минутные метрики по зонам: заказы, свободные, ожидание, тариф

дефицит(зона, 5 мин) = free_drivers / max(requests, 1) < 0.5  или  unfulfilled > 0

Случайность разделена на два независимых потока SeedSequence.spawn(2): эндогенный (спрос) и экзогенный (погода). Политика меняет цену, но погода во всех ветках остаётся одинаковой.

Модели

Общее туловище и multi-task головы

Тема курса — MLP, в ТЗ указана LSTM. Обучили обе: общий контракт «окно + зона → R» делает сравнение честным. Adam, lr 1e-3, batch 256, early stopping (patience 8). MLP обучается за 18,6 с.

Те же ступени, другая сеть

δ-калибровка порогов

Без калибровки сети вмешивались в 31–33 % окон. Сдвиг порога δ подобран так, чтобы обе вмешивались ровно в 10 %.

Равная информационная база

Каждый мир хранит «теневые» прогнозы обеих сетей, даже если политика их не использует. Разница между мирами объясняется только решением о цене.

python -m simulator.branches --all

Что видно. Все политики сокращают дефицит и ожидание. LSTM теряет меньше всех выручки и почти догоняет реактивную политику по дефициту.

Почему не лучше. Надбавка только гасит спрос через эластичность. Свободные водители на тариф не реагируют, поэтому раннему прогнозу нечем «отработать».

Следующий шаг · m6-supply-response

Тариф как сигнал водителям

В реальном такси надбавка притягивает машины. Если выставить тариф за 15 минут до дефицита, водители успеют доехать: путь между соседними зонами 5–10 мин.

  • Каждые 5 мин свободные водители решают, ехать ли в зону, где тариф выше хотя бы на 0,10
  • Уезжает до 30 % свободных машин, путь не длиннее 12 мин
  • Новое состояние relocating. Начатый переезд не отменяется
  • Правило детерминированное, флаг enabled: false сохраняет старые данные валидными

Город

Живая карта с машинами и дефицитом по зонам, перемотка в обе стороны через событийный лог и WebSocket, переключатель миров.

Лаборатория

Сравнение

Поездки, отказы, ожидание и кумулятивная выручка по веткам A/B/C/D.

# окружение
make install
# 30 дней мира и эпоха ML
make sim && make epoch && make epoch-check
# обучение и прогноз
python -m ml train --arch both
python -m ml infer
# калибровка политик и миры
python -m simulator.policy_calibration
python -m simulator.branches --all
# http://127.0.0.1:8000
make serve
